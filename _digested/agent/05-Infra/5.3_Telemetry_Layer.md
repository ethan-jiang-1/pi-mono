# 5.3 Telemetry 层：三包共用的追踪契约（v1.4.0）

> **本页基线：v1.4.0（`4a080252f`）。** 本页在 v1.4.0 新增。v1.2.0 时 `packages/telemetry` 只有 ai 一个消费者、且没有 propagation / links / metrics / store；v1.4.0 起它是 **ai / chord / durable 三包共用**的横切层，chord 甚至把它做成 `Context` 的必需成员。

## 它解决什么问题

Pi 要被嵌入到别人的进程里（SDK、durable worker、chord host、Cloudflare Durable Object），宿主可能用 OpenTelemetry、Sentry，也可能什么都不用。Pi 不能自带 exporter、也不能假设有全局 current-span。

所以 telemetry 包只定义**契约**：span、attribute、event、status、context。适配器把这些翻成后端概念；没有适配器时用 `NOOP_TELEMETRY_CONTEXT`，调用方代码零分支。

三条设计规则（`packages/telemetry/README.md:497-517`）：

1. **显式 context，不用全局变量。** `TelemetryContext` 是根的创建者，`TelemetrySpan` 是子 span 的父。宿主保留 adapter，业务侧只传 span。
2. **回调式生命周期。** `startSpan(options, cb)` 在回调 settle 时结算，没有公开的 `end()`；span 一定关。
3. **pi 不记录 prompt / 响应内容。** schema 层的属性都是 content-free 的（首事件、块大小、usage、错误类别），错误消息有长度上限。

## 核心契约

`packages/telemetry/src/index.ts`：

| 类型 | 作用 | 位置 |
|---|---|---|
| `TelemetryContext` | 创建 root span；可带 `metrics?`/`propagation?` 能力 | `index.ts:98-103` |
| `TelemetrySpan` | 子 span 的父；`startSpan`/`addEvent`/`setAttributes`/`setStatus`/`addLink` | `index.ts:105-110` |
| `SpanOptions` | `name` + `attributes` + `links` | `index.ts:24-28` |
| `SpanStatus` | `{status:"ok"}` 或 `{status:"error", error?:{name,message}}` | `index.ts:30` |
| `NOOP_TELEMETRY_CONTEXT` | 无 adapter 时的默认值，本身是 `TelemetrySpan` | `noop.ts:37` |

```ts
const span = telemetryContext.startSpan({ name: "example.load" }, async (span) => {
  span.addEvent("example.cache", { "example.cache.hit": true });
  return work();
});
```

注意 1.4.0 的 Breaking：**适配器现在必须实现 `addLink()`**（见下）；`NOOP_TELEMETRY_CONTEXT` 的类型也从 `TelemetryContext` 改成 `TelemetrySpan`。

## v1.4.0 的四个新增面

### 1. Propagation（跨进程/跨请求的 carrier）

`TelemetryCarrier = Record<string,string>`（不透明、adapter 拥有），`TelemetryPropagation{inject(ctx), extract(carrier)}`（`index.ts:9-18`）。挂在 `TelemetryContext.propagation?`、并随 span 向下传递。

- `extract(undefined)` 或无法识别的 carrier 回落 root；`NOOP_TELEMETRY_PROPAGATION` 是共享实例（`noop.ts:20`）。
- durable 用它在 admission 时把 carrier 存到 submission/task 上，重开任务时恢复 trace——这是"queued 输入也留在同一条 trace"的实现方式。

### 2. Span links（不是父子，是因果）

`SpanLink{context, attributes?}`（`index.ts:19-22`）、`SpanOptions.links`（`:24-28`）、迟到的 `span.addLink(...)`（`:105-110`）。

典型用途：一次 fan-out 里多个并行任务的 span 互不嵌套，但都 link 回同一个触发者。**links 不建立父子关系**，`renderTrace()` 也不会跟随它们。

### 3. Metrics（与 span 并列的一等公民）

`TelemetryMetrics{counter, upDownCounter, histogram}`（`metrics.ts:37-41`）；histogram 可给 `boundaries`（`:15-18`）。

`schema` 里可以声明指标：`TelemetryMetricDefinition.kind`（`:45-49`），`createTypedMetrics(adapter, schemas)` 把名字、种类、必填的低基数属性绑定起来（`:129-145`）。ai 的 `pi.ai.tokens`/`pi.ai.cost` 就是这么定义的。

### 4. Store 与渲染

`StoredSpan`（`index.ts:33-49`，settled 快照，事件时间相对 span 起点）、`StoredTrace`（`:50-53`）、`TelemetryStore{findTraces,getTrace,findMetrics}`（`index.ts:91-96`）。

`@earendil-works/pi-telemetry/render` 的 `renderTrace(spans)`（`src/render.ts:9-49`）输出纯文本 span 树：属性、耗时、error、事件 +Nms、`→ link trace … span …`。它**按 id 去重、从不跟随 link**，所以适合贴进 issue 或日志。

`InMemoryTelemetryContext`（`memory.ts:282`）是参考实现：实现 metrics（`:325-334`）、propagation（`:302-323`）、links、`findTraces/getTrace/findMetrics`（`:363-409`）。

## 三包如何接进来

| 包 | 接口 | 说明 |
|---|---|---|
| `ai` | `ProviderRequestOptions.telemetry?: TelemetrySpan`（`types.ts:159-166`） | 只包 chat 请求（`stream`/`streamSimple`/`streamDeferred`），**不包** `generateImages`/`classify` |
| `durable` | `HarnessOptions.telemetry?: TelemetryContext`（`harness/types.ts:611`） | 自己的 schema `DURABLE_TELEMETRY_SCHEMA`（`harness/telemetry.ts:50`）；把 phase span 透传给 pi-ai（`harness/generation.ts:224-231`） |
| `chord` | `Context.telemetry: TelemetrySpan`（`context/index.ts:13`） | **必需成员**；`withTelemetry(span)`、`traceIn`；另有 `@earendil-works/chord/telemetry-sqlite` 的 `SqliteTelemetry`（`TelemetryContext & TelemetryStore`） |

两条 schema：

- `AI_TELEMETRY_SCHEMA`（`packages/ai/src/telemetry.ts:63`）：spans `pi.ai.request` / `pi.ai.poll`；events `pi.ai.first_chunk` / `pi.ai.block`；metrics `pi.ai.request.duration`、`pi.ai.first_chunk.duration`、`pi.ai.tokens`、`pi.ai.cost`。错误 span 记 `provider_error`，消息截 500 字符；aborted 保持 `ok`；deferred poll **不计** token/cost。
- `DURABLE_TELEMETRY_SCHEMA`（`packages/durable/src/harness/telemetry.ts:50`）：spans `pi.durable.submit` / `pi.durable.phase`；metrics `reports` / `phase.duration` / `tasks.active`。失败 phase 记 `task_faulted|task_failed|task_orphaned`，诊断截 500 字符。

**谁在建根 span**：目前只有 durable 显式接 `TelemetryContext` 并把它传给 ai。coding-agent 不建 context（它的 `core/telemetry.ts` 只读 `PI_TELEMETRY` 开关来门控 attribution）。所以在 CLI 里跑时，ai 的请求 span 不会自动出现——需要宿主自己接。

## 反模式

- **不要持久化 `TelemetryContext` 或 span。** 它们是适配器对象/句柄，跨进程无意义；要跨进程就存 `TelemetryCarrier`。
- **不要用链接替代父子。** 一次调用链内的嵌套用 `span.startSpan()`；links 用于"因果相关但不同步"的并行工作。
- **不要把内容塞进属性。** schema 只允许低基数的枚举/数值/布尔；prompt 与工具输出永远不进 telemetry。
