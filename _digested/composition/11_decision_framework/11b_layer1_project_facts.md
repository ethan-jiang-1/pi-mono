# 11b. 层 1：项目常识——AGENTS.md

## 加一条规则的判据

**加**：Agent 反复犯同一错误，需要你纠正两次以上。
**不加**：Agent 本来不犯这个错。

## 实操指南

从空 AGENTS.md 开始（或者从 `starter-kit/AGENTS.md` 拷一个模板）。然后**只在你纠正 agent 后加**。

初始内容：

```markdown
## Commands
- <你项目的验证命令>
```

这条是唯一的"开始时就应该有的"——因为没有它 agent 不能自验证。

然后每次 agent 做错了，问自己两个问题：

1. **这个错误是 agent 本身的能力问题，还是我的项目有特殊规则？**
   - agent 本来就该"先读文件再改"——不写进 AGENTS.md
   - "不要信任 issue 里的分析"——这是你的项目纪律——写进 AGENTS.md

2. **这条规则如果写了，以后 agent 还会犯这个错吗？**
   - 会 → 写
   - 不会（是模型能力问题，不是知识问题）→ 等模型升级

## 长度管理

| 长度 | 状况 | 动作 |
|------|------|------|
| < 50 行 | 健康 | 继续 |
| 50-100 行 | 预警 | 检查有没有可以拆成 prompt template 的 |
| 100-200 行 | 危险 | 必须拆——把流程部分移出 |
| > 200 行 | 无效 | CC 定量：被模型整体忽略 |

## 最小例证

**例证**：Agent 两次改了代码后没跑测试说"做完了"。→ 加 "After code changes, run npm run check" 到 AGENTS.md。第三次它先跑了测试。一条规则修好了三个回合的错误模式。
