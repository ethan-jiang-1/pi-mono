# 4.2 Skills：从文件到 prompt 的能力注入机制

> **⚠️ v0.83.0**：`skills.ts` 仅 import style 变化（`.js`→`.ts`），无实质 API 变更。行号基本有效。
>
> **⚠️ v0.84.2**：v0.84 修复 Windows 递归 skill 加载的路径处理，无 API 变化。行号未复核。

## 现象是什么

pi-mono 有一个 skills 系统：用户或扩展可以在特定目录放 `SKILL.md` 文件，定义专门的领域知识和操作指令。当 LLM 需要执行特定领域的任务时，它可以"调用"对应的 skill——实际上就是把 skill 的完整内容注入当前对话。

从外部看：有一个 `<available_skills>` XML block 在 system prompt 里列出所有可用 skill；有一个 `<skill name="..." location="...">` 的引用格式把 skill 内容注入用户消息。

## 核心矛盾是什么

Skills 不是普通的 prompt 指令。它们有几个特殊要求：

1. **发现（discovery）**：需要递归遍历目录找到 `SKILL.md`，但要遵守 `.gitignore`/`.ignore`/`.fdignore`
2. **解析（parsing）**：YAML frontmatter 包含元数据，body 是实际内容
3. **注入（injection）**：有两种方式——model-driven（LLM 看到 skill 列表后主动决定使用）和 direct（用户或程序显式调用 `harness.skill(name)`）
4. **容错（resilience）**：一个 skill 文件解析失败不应该阻止其他 skill 加载或应用启动

核心矛盾：**Skills 是文件系统中的非结构化知识，但需要变成结构化的 agent 能力，而且加载过程必须鲁棒。**

## 实现思想是什么

### Skill 接口

```typescript
interface Skill {
  name: string;                    // 稳定名称，用于查找和 LLM 可见列表
  description: string;             // 简短描述，告诉 LLM 什么时候用
  content: string;                 // 完整指令内容
  filePath: string;                // SKILL.md 的绝对路径（用于 LLM 解析相对引用）
  disableModelInvocation?: boolean; // 不显示在 <available_skills> 中，只能显式调用
}
```

### 加载流程（loadSkills）

`loadSkills(env, dirs)` 接收一个或多个目录路径，返回 `{ skills, diagnostics }`：

1. **入口检查**：对每个目录，先 `fileInfo(dir)` 检查是否存在。`not_found` 直接跳过（不报错），其他错误记录为 diagnostic
2. **递归扫描**：`loadSkillsFromDirInternal()` 递归遍历目录树
3. **Ignore 规则**：在每个目录中查找 `.gitignore`、`.ignore`、`.fdignore`，用 `ignore` 库构建匹配器。路径前缀会根据相对于 root dir 的位置自动处理（例如 subdir 中的 pattern 会加上 subdir/ 前缀）
4. **Skill 文件匹配**：优先找 `SKILL.md`（name 是严格的 `SKILL.md`），如果目录中没有，再扫描其他 `.md` 文件（仅在 root dir 的第一层）
5. **目录过滤**：跳过 `.` 开头的隐藏目录和 `node_modules`
6. **符号链接处理**：通过 `resolveKind()` 先检查 kind，如果是 symlink 则用 `canonicalPath()` 解析目标后再判断

### YAML Frontmatter 解析

`parseFrontmatter()` 使用简化的 frontmatter 解析器（不依赖 gray-matter）：

1. 如果不是以 `---` 开头，整个内容就是 body
2. 如果找到 `---` 分隔符，提取中间部分用 `yaml` 库的 `parse()` 解析
3. 支持的 frontmatter 字段：
   - `name`: skill 名称（如果不提供，使用父目录名）
   - `description`: 描述（**必需**，没有的话 skill 不会被加载）
   - `disable-model-invocation`: 不在 `<available_skills>` 中列出
4. 验证规则：
   - name 必须和父目录名匹配（不一致会报警告但不会阻止加载）
   - name 只能包含 `[a-z0-9-]`，不能以 `-` 开头/结尾，不能有连续 `--`
   - name 最长 64 字符，description 最长 1024 字符

### 两种注入路径

**路径 A - Model-driven（LLM 自主选择）：**

`formatSkillsForSystemPrompt(skills)` 生成 `<available_skills>` XML block：

```xml
The following skills provide specialized instructions for specific tasks.
Read the full skill file when the task matches its description.
When a skill file references a relative path, resolve it against the skill directory...

<available_skills>
  <skill>
    <name>pdf-processing</name>
    <description>Extract, merge, and convert PDF files</description>
    <location>/home/user/.pi/agent/skills/pdf-processing/SKILL.md</location>
  </skill>
</available_skills>
```

这个 block 会出现在 system prompt 中。当 LLM 判断任务匹配某个 skill 的描述时，它会通过 read 工具读 `SKILL.md` 文件。

**路径 B - Direct invocation（程序显式调用）：**

```typescript
await harness.skill("pdf-processing", "Extract pages 1-5 from report.pdf");
```

`formatSkillInvocation(skill, additionalInstructions)` 生成：

```xml
<skill name="pdf-processing" location="/home/.../SKILL.md">
References are relative to /home/.../skills/pdf-processing.

[skill content]
</skill>

Extract pages 1-5 from report.pdf
```

整个 XML block 作为用户消息发送给 LLM。`AgentSession.parseSkillBlock()` 会解析这种格式，提取 skill 元信息和额外的用户指令。

### 扩展来源的 Skills

`loadSourcedSkills()` 支持带来源标记的加载。当 extension 在 `resources_discover` 事件中返回 skill 路径时，每个 skill 会带上 `source`（通常是 extension path），允许应用区分 skill 来源并做相应的路径处理。

### 诊断系统

`loadSkills()` 不会因为单个文件的加载失败而崩溃。所有失败都以 `SkillDiagnostic` 的形式返回：

```typescript
interface SkillDiagnostic {
  type: "warning";         // 目前只有 warning
  code: SkillDiagnosticCode; // file_info_failed | list_failed | read_failed | parse_failed | invalid_metadata
  message: string;
  path: string;            // 关联的文件路径
}
```

这种行为保证了一个损坏的 `SKILL.md` 不会让整个应用启动失败。

## 在 Agent 能力面里的影响是什么

1. **Skills 是知识注入的标准通道**。任何需要"特定领域深度知识"的场景（PDF 处理、数据库迁移、部署流程）都通过 skills 注入，而不是硬编码在 system prompt 里。

2. **模型自主调用 + 程序显式调用双路径**。模型可以通过 system prompt 中的 `<available_skills>` 列表知道有哪些 skills 可用，程序也可以通过 `harness.skill()` 强制使用某个 skill。

3. **Skills 的 "location" 是真实文件路径**。这意味着 LLM 可以通过 read 工具访问 skill 文件的完整内容，而且 skill 内容中的相对路径引用是可解析的。

4. **加载的容错性保证了稳定性**。任何一个 skill 文件的格式错误不会影响整体系统。

## 最小例子是什么

```typescript
import { loadSkills, formatSkillsForSystemPrompt, formatSkillInvocation } from "@earendil-works/pi-agent-core/harness";

// 1. 加载 skills（容错，返回 diagnostics）
const { skills, diagnostics } = await loadSkills(env, ["/home/user/.pi/agent/skills"]);
if (diagnostics.length > 0) {
  console.warn("Skill loading warnings:", diagnostics);
}

// 2. 生成 system prompt 块
const skillBlock = formatSkillsForSystemPrompt(skills);
// 输出:
// <available_skills>
//   <skill>
//     <name>pdf-processing</name>
//     <description>...</description>
//     <location>...</location>
//   </skill>
// </available_skills>

// 3. 显式调用一个 skill
const mySkill = skills.find(s => s.name === "pdf-processing")!;
const prompt = formatSkillInvocation(mySkill, "Merge these files");
// 输出: "<skill name=\"pdf-processing\" location=\"...\">\n...content...</skill>\n\nMerge these files"

// 4. 如果需要 disable model invocation（只在显式调用时可用）
const hiddenSkill = {
  name: "internal-cleanup",
  description: "Internal cleanup routines",
  content: "Remove temp files...",
  filePath: "/path/to/SKILL.md",
  disableModelInvocation: true, // 不会出现在 <available_skills> 中
};
```
