# 6 · 空白：必须有但还没有头部的位置

按"离流量/信任入口的远近"排序。每条给：现状证据 → 为什么是空位 → 做成什么样算成。

## 6.1 包的质量/安全审计层（信任入口）

- **现状**：5412 个包，`pi install` 即任意代码执行；官方只有人工 report 模板；无评分、无权限声明、无自动审计。Implicator 把供应链列为头号隐忧。
- **空位**：npm 世界有 npm-audit/Snyk/权限清单，pi 生态对应物完全缺失。
- **做成**：装包前展示"这个包注册了哪些钩子/工具/权限 + 社区评分 + 源码 diff 审计"；做到"装包决策有依据"即成。
- **难度**：中。数据都在扩展 API 里（registerTool/事件清单可静态分析）。

## 6.2 搜索/发现层（流量入口）

- **现状**：gallery 只有名称/描述过滤；无语义搜索、无"装了 A 的人也装 B"、无类别导航；索引滞后 npm（#6991）。
- **空位**：长尾 4000 个包基本不可见。pi.dev 自己不做（官方克制），第三方可做。
- **做成**：语义搜索 + 使用共现推荐 + "包的 awesome 图谱"。谁能帮用户在 5 分钟内配好默认套装，谁拿流量。

## 6.3 包间依赖 + monorepo 子目录安装（平台标准件）

- **现状**：官方两连拒（#4269、#4530）。38 个头部 bundle 全在手工拷贝聚合（@llblab/pi-kit、reddb-io 系列、DoomPi 套件各自造轮子）。
- **空位**：官方不做 = 社区标准。一个"包清单管理器"（声明依赖、锁定版本、一键装全家）就能占住。
- **做成**：`pi install @kit/something` 自动拉齐依赖树，bundle 作者不再复制粘贴。

## 6.4 包管理可靠性（高频痛点）

- **现状**：issue 区第一大类——pnpm/bun/npm 互操作重装、全局根解析、jiti 解析失败（#4501、#3000、#3809、#2072、#8112）。
- **空位**：官方在逐个修，但"包安装策略"整体方案缺位。
- **做成**：不一定是独立包——给官方提 PR 或写一篇"各种包管理器下 pi 包的安装策略"就有影响力。这是**离核心最近的贡献位**。

## 6.5 统一定时/守护任务

- **现状**：cron/routine 散落在 task-factory、omp-deck（cron routines）、pi-background-tasks 里，无标准件。
- **做成**：`pi cron "每天 9 点 review 昨天的 diff"`——一个声明式定时任务标准件，编排类会自动长在它上面。

## 6.6 扩展包评测/回归

- **现状**：唯一正规入口是 pi-terminal-bench（badlogic 的 Harbor adapter）；针对"包"的评测层空缺。
- **空位**：包作者没有 CI 标杆（@trim21 0.1.527 版本号的狂奔节奏说明大家都在裸奔）。
- **做成**：包兼容性矩阵（pi 版本 × 包版本 × 测试结果），像 DefinitelyTyped 那样按 pi 版本门控。

## 6.7 Windows/WSL 一等公民

- **现状**：官方 0.84 才补 PowerShell 工具和键位避让；生态侧 bwrap/nono 沙箱全是 Linux/macOS；头部包多数假定 Unix。
- **做成**：Windows 可用的沙箱 + 会话管理 + 通知层。用户群不小，竞争者为零。

## 6.8 知识/RAG 站（下一个卷点）

- **现状**：主类仅 25 包但增速看涨：mem0 集成（32K）、qmd 语义检索（pi-memory 39K）、llm-wiki（11K）、pi-graphify。
- **空位**："agent 长期记忆的本地知识库"没有标准件——存储格式、检索接口、更新策略都未收敛。
- **做成**：定义一个本地知识库格式让所有记忆包互通，成为事实标准。

## 6.9 一个综合判断

上面的空位分三类，做的人也不同：

| 类型 | 例子 | 谁适合做 |
|---|---|---|
| 平台级（和官方抢/补官方） | 6.3、6.4、6.6 | 想进核心圈的贡献者（先 PR 后标准） |
| 入口级（流量/信任） | 6.1、6.2 | 产品型团队（gallery 2.0、audit 工具） |
| 内容级（品类深耕） | 6.5、6.7、6.8 | 个人开发者（每个都是 3 个月窗口） |
