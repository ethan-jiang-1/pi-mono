# 3.2 Branch Summary: 分支导航的记忆桥梁

> **⚠️ v0.83.0**：`BranchSummaryResult` 新增 `usage` 字段；summarization 新增 retry 支持。行号全部失效。

## 现象是什么

当用户在 Session tree 中从当前 leaf 跳转到历史中的某个点（`moveTo(entryId, summary)`）时，pi-mono 会将被"遗弃"的分支内容自动总结为一个分支摘要，并在后续回到该分支时（或从该分支 fork 新对话时），将这个摘要注入到上下文开头。这样模型就能理解"你之前在这个分支上做了什么，为什么回到了这里"。

**源码位置：** `/packages/agent/src/harness/compaction/branch-summarization.ts`

## 核心矛盾是什么

Session tree 的分支导航创造了"多路径对话历史"。当用户从 branch A 跳到 branch B，再从 B 回到 A 时，模型需要理解：

1. **在 B 上发生了什么？** 这些信息对于理解"为什么回到 A"可能至关重要（例如"在 B 上尝试了方案 X 但失败了"）。
2. **B 上产生的工作产物**（读过的文件、改过的文件）**是否与 A 的任务相关？** 如果相关，模型需要知道。
3. **摘要的预算限制：** 不能把 B 的全部对话历史塞进 A 的上下文，成本太高，信息密度太低。

## 实现思想是什么

### collectEntriesForBranchSummary

当用户执行 `moveTo(targetId)` 时，系统需要确定哪些 entry 需要被总结。算法：

```
输入: session, oldLeafId (当前 leaf), targetId (目标节点)
1. 获取 oldPath = getBranch(oldLeafId) 的所有 entry id
2. 获取 targetPath = getBranch(targetId)
3. 从 targetPath 末尾向前，找到与 oldPath 的交集 → commonAncestorId
4. 从 oldLeafId 向上走到 commonAncestorId，收集这条路径上的所有 entry
5. 反转顺序（使之为从旧到新的时间序）
```

结果是一个"废弃分支"上的 entry 列表。这些 entry 被交给 `generateBranchSummary()` 生成摘要。

### prepareBranchEntries

在生成摘要前，需要将 entry 转换为 messages 并限制 token 预算：

```typescript
function prepareBranchEntries(entries: SessionTreeEntry[], tokenBudget: number): BranchPreparation
```

转换规则：
- `MessageEntry`（非 toolResult 的）→ 提取 message
- `CustomMessageEntry` → 创建 custom message
- `BranchSummaryEntry` → 创建 branchSummary message
- `CompactionEntry` → 创建 compactionSummary message
- `toolResult` → 跳过（不进入摘要上下文）
- `thinking_level_change`、`model_change`、`custom`、`label`、`session_info`、`leaf` → 跳过

预算控制：从最新的 entry 开始向前累积，直到达到 `tokenBudget` 的 90%。对于 compaction/branch_summary entry，即使会超出预算，如果当前累积小于 90% 预算，也会被包含（确保结构性摘要不被丢失）。

### generateBranchSummary

使用与 Compaction（3.1）相同的摘要格式：

```
## Goal
[用户在这个分支上想完成什么？]

## Constraints & Preferences
- [约束和偏好]

## Progress
### Done
- [x] [已完成]

### In Progress
- [ ] [进行中]

### Blocked
- [阻塞项]

## Key Decisions
- **[决策]**: [理由]

## Next Steps
1. [后续步骤]
```

与 Compaction 的不同：
- 分支摘要前面有一个固定的 preamble：`"The user explored a different conversation branch before returning here. Summary of that exploration:\n\n"`，这告诉模型：这是一个不同的上下文。
- 分支摘要使用 `maxTokens: 2048`（而非 compaction 使用 `0.8 * reserveTokens`），因为分支摘要的详细程度不需要像 compaction 那么高。
- `tokenBudget = model.contextWindow - reserveTokens`（默认 `reserveTokens = 16384`），确保摘要 prompt + 摘要输出不会超出上下文窗口。

### BranchSummaryEntry 持久化

`moveTo(entryId, summary)` 在 session tree 中插入一个 `BranchSummaryEntry`：

```typescript
{
  type: "branch_summary",
  id: ...,
  parentId: entryId,   // 指向跳转到的目标节点（而非旧 leaf）
  timestamp: ...,
  fromId: entryId ?? "root",
  summary: "总结文本...",
  details: { readFiles, modifiedFiles },
}
```

关键设计：`parentId` 指向的是 `entryId`（目标节点），而非原来废弃分支上的节点。这意味着从目标节点向上走树时，会经过这个 BranchSummaryEntry。

### 在 buildSessionContext 中的使用

在 `buildSessionContext()` 中（参见 3.4），`BranchSummaryEntry` 被转换为一条 `branchSummary` role 的 AgentMessage，注入到上下文最前面。同时，BranchSummaryEntry 中记录的 `fromHook` 和文件操作列表也参与后续的文件操作追踪。

## 在 Agent 能力面里的影响是什么

- **分支间的连续感：** 用户跳回旧分支时，模型看到的第一条消息就是"你在另一个分支上做了什么"，从而给出连续的建议。
- **尝试-回退的工作流：** 用户尝试方案 X → 不满意 → 回到主分支 → 模型理解"方案 X 失败了"而不是从头开始。
- **文件操作的知识传递：** BranchSummaryEntry 的 details 中记录了 readFiles 和 modifiedFiles，这意味着后续的 compaction 和文件追踪可以感知到跨分支的文件操作。

## 最小例子是什么

```typescript
import { 
  collectEntriesForBranchSummary, 
  generateBranchSummary 
} from "@earendil-works/pi-agent";

// 当前在某个分支上工作，要跳回 main 分支
const oldLeafId = await session.getLeafId();  // "entry-main-branch-tip"
const targetId = "entry-original-question";    // 要跳回的点

// 收集废弃分支上需要总结的 entries
const { entries, commonAncestorId } = await collectEntriesForBranchSummary(
  session, oldLeafId, targetId
);
console.log(`需要总结 ${entries.length} 个 entry，commonAncestorId = ${commonAncestorId}`);

// 生成分支摘要
const result = await generateBranchSummary(entries, {
  model: claudeSonnet,
  apiKey: "sk-...",
  signal: new AbortController().signal,
  reserveTokens: 16384,  // 留给 prompt + 输出的预算
});

if (!result.ok) {
  console.error("分支摘要生成失败:", result.error.message);
} else {
  console.log("分支摘要:", result.value.summary.slice(0, 300));
  console.log("读过的文件:", result.value.readFiles);
  console.log("修改过的文件:", result.value.modifiedFiles);
}

// 执行跳转
await session.moveTo(targetId, {
  summary: result.value.summary,
  details: { 
    readFiles: result.value.readFiles, 
    modifiedFiles: result.value.modifiedFiles 
  },
});

// buildContext 现在会包含 branchSummary 消息作为第一条上下文
const newContext = await session.buildContext();
// newContext.messages[0].role === "branchSummary"
// newContext.messages[0].summary === result.value.summary
```

这个例子展示了分支导航的完整记忆桥梁：收集废弃分支内容 → 生成结构化摘要 → 持久化为 BranchSummaryEntry → 在新上下文中作为前缀注入。
