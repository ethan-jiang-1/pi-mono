## 现象是什么

v0.83.0 中 `packages/ai/src/` 新增了 `api/` 目录，把原来混在 `providers/` 里的 wire-protocol 实现（怎么调 Anthropic Messages API、怎么调 OpenAI Responses API...）拆出来成为独立层。截至 v0.84.2 该目录有 **32 个文件**：11 个 API 实现 + 11 个 lazy wrapper + 10 个共享/基础设施文件。每个 stream API 有两个文件：一个实现（如 `anthropic-messages.ts`）+ 一个 lazy wrapper（如 `anthropic-messages.lazy.ts`）（~~openrouter-images 是图片生成 API~~——v1.0.0 已删除，图像模型并入 openrouter 主 catalog，见顶部横幅）。同时 `auth/` 和 `compat/` 也从 providers 中拆出。

## 核心矛盾

**API adapter 的代码很重。** `bedrock-converse-stream.ts` ~42KB 带 AWS SDK 依赖，`openai-responses-shared.ts` 有复杂的 tool output 转换逻辑。如果启动时 eager-load 所有 adapter，即使只用 Anthropic，也要为 AWS SDK、Google SDK、OpenAI SDK 付出 import 成本（Mistral v0.84 起改走原生 `fetch`，不再拖 SDK）（硬事实）。

解法：**lazy loading 模式** — 从 `.lazy.ts` import 几乎是零成本的（一个闭包），真正的模块在第一次 `stream()` 调用时才加载（解释）。

## 实现思想

### 三层架构

```
providers/   →  "有什么模型"（Model catalog，纯数据）
api/         →  "怎么调 API"（Wire-protocol streaming）
auth/        →  "用什么凭证"（Credential resolution）
```

调用链：`Models.streamSimple()`（pi-ai 内接口；coding-agent 的 `ModelRuntime implements Models` 并委托给它）→ 按 model 的 `api` 字段 dispatch → 找到对应的 `ProviderStreams` → 调 `stream()` 或 `streamSimple()`。

### deferred response 契约（v0.84 新增）

`SimpleStreamOptions.deferred?: boolean | { window?: "15m" | "1h" | "24h" }` 请求 provider 返回 **durable handle** 而非即时响应（`StopReason` 新增 `"deferred"`）。之后用 `Models.fetchDeferred(model, handle, options)` 取回（long-poll `wait` 参数）、`Models.cancelDeferred(model, handle, options)` 取消——两者都走 `applyAuth()` 做 authenticated dispatch（硬事实）。`ProviderStreams` 上的 `fetchDeferred?/cancelDeferred?` 是可选方法；`createProvider()` 仅在任一 API 实现提供时才在 provider 上挂载；`lazyApi(load, { fetchDeferred, cancelDeferred })` 可以为 lazy wrapper 声明同样的 capability（硬事实）。内置 adapter 尚未实现该契约，`providers/faux.ts` 是参考实现/测试替身（推测）。

### lazyApi 和 lazyStream

`lazy.ts` 导出两个函数：

**`lazyApi(load, capabilities?): ProviderStreams`** — 接收 `() => import("./xxx.ts")`，返回一个 `{ stream, streamSimple }` 对象（v0.84 起可选 `{ fetchDeferred, cancelDeferred }` capabilities，为 deferred 方法包一层同样的 lazy dispatch）。首次调用任一方法时触发 `load()`，结果缓存在模块闭包中。后续调用直接走缓存。

**`lazyStream(model, setup): AssistantMessageEventStream`** — 更深的技巧：**同步返回**一个 `AssistantMessageEventStream`，而 `setup()` 在后台异步运行（硬事实）。如果 setup 失败（模块加载失败、auth 错误），错误编码为 stream 上的 error event，永不 throw（硬事实）。

这意味着调用方总是立即拿到 stream 对象——不需要 `await`。网络请求 + 模块加载并行进行（解释）。

### Stream 函数合约

每个 API 模块导出两个函数（能力强的还可以导出 deferred 方法），遵守相同的合约：

```ts
stream(model, context: TranscriptContext, options?) → AssistantMessageEventStream
streamSimple(model, context: TranscriptContext, options?) → AssistantMessageEventStream
fetchDeferred?(model, handle, options?) → AssistantMessageEventStream   // 可选
cancelDeferred?(model, handle, options?) → Promise<void>               // 可选
```

> ⚠️ v0.86.1（#9548）：`context` 参数是 branded `TranscriptContext`（由 `normalizeContext()` 从 `Context` 归一化而来），SystemMessage 序列携带 prompt/tools 增量；见顶部 v0.85.x–0.86.x 警示 ①。

合约规则：
- **永不 throw**（硬事实）。所有错误（网络、auth、parse）编码为 stream event
- **成功**：`{ type: "done", reason: "stop" | "length" | "toolUse" | "deferred", message: AssistantMessage }` → stream 结束（硬事实）
- **失败**：`{ type: "error", reason: "aborted" | "error", error: AssistantMessage }` → `AssistantMessage` 带 `stopReason: "error"/"aborted"` 和 `errorMessage`（硬事实）

`stream` 接收 provider-specific 的 typed options（如 `OpenAIResponsesOptions` 有 `reasoningEffort`）。`streamSimple` 接收统一的 `SimpleStreamOptions`（有 `reasoning`、`thinkingBudgets`、`deferred`，v0.84.3 起还有 `toolChoice`），内部通过 `buildBaseOptions()` 自动 clamp maxTokens 到 context window 安全边界、做**三层采样参数合并**（`resolveSamplingParams()`：`model.samplingParams` ← 按有效 thinking level 的 `samplingParamsByThinkingLevel` ← 请求级 `samplingParams` 逐层覆盖，`simple-options.ts:24-32`；三层合并为 v1.0.2 增量），然后调用 `stream`（硬事实）。

### 每个 `.lazy.ts` 的结构

所有 lazy wrapper 都是同一模式的一行代码：

```ts
// anthropic-messages.lazy.ts
export const anthropicMessagesApi = (): ProviderStreams => lazyApi(() => import("./anthropic-messages.ts"));
```

Bedrock 是个例外——它用变量字符串（非字面量）传 import path，防止 bundler 追踪到 Node-only 的 AWS SDK。同时暴露 `setBedrockProviderModule` 供 Bun binary 注入静态 bundle。

### cross-provider 共享模块

`transform-messages.ts` — 跨 provider 消息标准化：image downgrade、tool-call ID 重写、orphaned tool-call padding、加密 thinking signature 剥离。

`constrained-sampling.ts` — grammar-based 约束 JSON 采样 + JSON Schema strict mode 解析。工具可以声明 `constrainedSampling` 配置（`json_schema strict: prefer|require` 或 `grammar` variants），API adapter 据此启用 provider 的 structured output 能力。

`openai-responses-shared.ts` — OpenAI Responses 家族的共享转换逻辑（tool output → message、text signature 编码、caching helper、`additional_tools` deferred tool loading）。

`google-shared.ts` — Google Generative AI 与 Vertex 两个 adapter 的共享转换逻辑。

其余小共享件：`openai-prompt-cache.ts`（prompt cache key 64 字符截断）、`github-copilot-headers.ts`（`X-Initiator` / `Copilot-Vision-Request` header 推断）、`cloudflare.ts`（Workers AI / AI Gateway base URL 常量）、`cloudflare-ai-binding.ts`（v0.85.0 起取代 cloudflare-gateway-binding：`createAiBindingFetch()` 把 gateway HTTPS 请求翻译成 Workers AI binding 调用，baseUrl 直接配置 passthrough）、`opencode-headers.ts`（`x-opencode-session` session-affinity，v0.86.x 新增）、`azure-openai-config.ts`（v1.0.3 新增，Azure endpoint/deployment 解析与 `AZURE_OPENAI_DEPLOYMENT_NAME_MAP`，Responses 与 Chat Completions 两个 API 共用）、`utils/transcript.ts`（`normalizeContext`/`getCurrentSystemPrompt`/`getCurrentTools`/`collapseSystemMessages`——TranscriptContext 归一化层，v0.86.x 新增）。

## 在 Agent 能力面里的影响

- **启动零成本**。import `@earendil-works/pi-ai` 不再加载 AWS SDK、Google SDK 等重型依赖。
- **添加新 provider** 只需：实现 `ProviderStreams` 合约 + 写一行 lazy wrapper + 在 `compat.ts` 的 `BUILTIN_APIS` 表中注册。
- **错误面统一**。所有 API 错误以 event 形式流入 Agent loop，不需要 per-provider try/catch。
- **`streamSimple` 是外部集成的最简路径**：只传 model + context + reasoning level，maxTokens 自动 clamp。

## 最小例子

直接使用一个 lazy API adapter：

```ts
import { anthropicMessagesApi } from "@earendil-works/pi-ai/api/anthropic-messages.lazy";

const api = anthropicMessagesApi(); // 零成本——还没加载 Anthropic SDK

const stream = api.streamSimple(model, context, {
  reasoning: "high",
  apiKey: "sk-...",
});
// stream 是同步返回的 AssistantMessageEventStream
// Anthropic SDK 在第一次 stream 调用时才 import

for await (const event of stream) {
  if (event.type === "text_delta") console.log(event.delta);
  if (event.type === "done") break;
}
```
