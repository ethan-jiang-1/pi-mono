## 现象是什么

pi-mono 的 bash 工具让 LLM 可以执行 shell 命令。从 LLM 的视角看，它跟其他工具一样：一个 `command` 参数加可选的 `timeout`。但从实现视角看，bash 是 pi-mono 中最复杂的工具——它涉及进程管理、流输出、取消、输出截断、权限控制、渲染优化。

用户在 TUI 中看到的是：命令执行时输出**增量出现在工具卡片中**，不是等命令结束后一次性刷出来。如果输出太长，会被截断到 temp 文件中。如果按了 interrupt，进程树会被清理。

## 核心矛盾是什么

Bash 工具的核心矛盾来自**长生命周期进程 vs 短生命周期事件循环**：

1. `execute()` 是 async 函数，但 bash 命令可能运行几分钟甚至无限
2. 输出在命令执行过程中持续产生，UI 需要增量渲染
3. 取消（abort）需要杀死整个进程树，不能留下孤儿进程
4. 输出可能非常大（GB 级），不能全放在内存中的字符串
5. 超时（timeout）需要可靠的进程终止

## 实现思想是什么

### 两层结构

Bash 工具有两层实现：

**上层（tools/bash.ts）**：`createBashToolDefinition()` 和 `createBashTool()`。处理工具定义、参数验证、渲染、输出累积和截断。

**下层（bash-executor.ts）**：`executeBashWithOperations()`。处理进程生成、流输出、取消、截断到 temp 文件。被 AgentSession 直接调用（用于用户主动执行的 bash），也被 bash 工具通过 `BashOperations` 接口间接调用。

### BashOperations 接口

bash 工具的执行不是硬编码的。通过 `BashOperations` 接口，可以替换底层执行实现：

```typescript
interface BashOperations {
  exec(command, cwd, options: {
    onData: (data: Buffer) => void;  // 流输出回调
    signal?: AbortSignal;            // 取消信号
    timeout?: number;                // 超时秒数
    env?: NodeJS.ProcessEnv;         // 环境变量
  }): Promise<{ exitCode: number | null }>;
}
```

默认实现 `createLocalBashOperations()` 使用 Node.js 的 `spawn()`。但这个接口也可以被 extensions 替换为远程执行（SSH、container 等）。

### 进程管理（bash-executor.ts）

`executeBashWithOperations()` 的核心流程：

1. **输出缓冲**：使用 rolling buffer（`outputChunks` 数组），最大保留 `DEFAULT_MAX_BYTES * 2`（默认 100KB）的内容。这是为了在 truncation 时总能有足够的尾部内容。

2. **流输出**：每个 data chunk 经过 `sanitizeBinaryOutput(stripAnsi(text))` 处理后，通过 `options.onChunk` 回调传播。这对 UI 增量渲染至关重要。

3. **Temp 文件处理**：当总输出超过 `DEFAULT_MAX_BYTES`（默认 50KB）时，自动创建 temp 文件。之前累积的 chunks 先写入 temp 文件，后续内容直接写 temp 文件。最终 temp 文件路径通过 `fullOutputPath` 返回。

4. **截断**：使用 `truncateTail()` 保留输出的最后 `DEFAULT_MAX_LINES` 行（默认 200 行）或 `DEFAULT_MAX_BYTES` 字节。截断信息通过 `truncation` 字段返回。

5. **取消处理**：检查 `signal.aborted`，如果被取消，仍然返回已有输出（不丢失），但 `exitCode` 为 `undefined`，`cancelled` 为 `true`。

### 进程生成和信号取消（tools/bash.ts）

`createLocalBashOperations()` 的实现细节：

1. **Shell 选择**：通过 `getShellConfig()` 确定 shell 路径和参数。Unix 上用 `bash -c` 或用户配置的 shell。

2. **Detached 进程**：`spawn()` 使用 `detached: process.platform !== "win32"`。这意味着子进程在自己的进程组中运行，Eshell 退出不会牵连父进程。

3. **信号取消**：
   - `AbortSignal` 触发 → `killProcessTree(child.pid)` 使用 SIGTERM → 如果进程没退出则升级到 SIGKILL
   - `timeout` 触发 → 同样调用 `killProcessTree()`
   - `waitForChildProcess()` 等待进程退出，同时处理 detached 子进程的 stdio 持有问题

4. **stdout/stderr 合并**：`child.stdout` 和 `child.stderr` 都通过相同的 `onData` 回调处理。在工具层面，输出被 `OutputAccumulator` 累积。

### BashSpawnHook

在命令执行前，`resolveSpawnContext()` 可以被 `BashSpawnHook` 修改：

```typescript
type BashSpawnHook = (context: BashSpawnContext) => BashSpawnContext;
// BashSpawnContext: { command, cwd, env }
```

这个 hook 允许在命令执行前改写命令本身、工作目录或环境变量。例如，可以在所有命令前加 `set -euo pipefail`。

### 输出流控（OutputAccumulator）

`OutputAccumulator` 类负责累积二进制输出并生成快照：

- `append(data: Buffer)`：累积输出
- `finish()`：标记结束
- `snapshot({ persistIfTruncated })`：获取当前输出快照，如果被截断则触发 temp 文件写入
- 流控：`BASH_UPDATE_THROTTLE_MS = 100` 毫秒的 throttle，避免 UI 刷新过于频繁

### 工具定义中的渲染

Bash 工具实现了三个渲染回调：

- `renderCall(args, theme, context)`：显示 `$ command` 的样子，实时更新 duration timer
- `renderResult(result, options, theme, context)`：显示输出内容（折叠/展开）、截断警告、完整输出路径、耗时

渲染时使用 `BASH_PREVIEW_LINES = 5` 行预览（未展开状态），显示最后 5 行。duration 用一个 1s interval 定时器驱动。

### Permission 集成

Bash 工具通过 AgentHarness 的 `beforeToolCall` hook 与权限系统集成。在 AgentSession 中：

```typescript
// ExtensionRunner.emitToolCall() 被调用
// handler 可以返回 { block: true } 阻止命令执行
```

这允许 extensions 在命令执行前做安全检查（例如检查是否包含 `rm -rf /` 等危险模式）。

### 命令意图压缩

当 bash 命令的输出被纳入 context 时，可能需要压缩。输出经过 truncation 处理，保留最有信息量的尾部内容。

## 在 Agent 能力面里的影响是什么

1. **Bash 是 LLM 访问文件系统的主要通道**。没有 bash，LLM 只能用 read/edit/write 工具做有限的文件操作。

2. **流输出是良好 UX 的基础**。100ms throttle 的增量更新让用户看到命令正在运行，而不是卡住等待。

3. **BashOperations 接口让执行可以重定向**。SSH、container、sandbox —— 只要实现了 `exec()` 方法，就可以替换本地 shell 执行。

4. **Cancellation 是安全的**。`killProcessTree` 确保整个进程树被清理，不会有孤儿进程残留。

## 最小例子是什么

```typescript
import { createBashTool, createLocalBashOperations } from "@earendil-works/pi-coding-agent/core";
import { AgentHarness } from "@earendil-works/pi-agent-core";

// 1. 使用默认的本地 bash 执行
const bashTool = createBashTool("/path/to/project", {
  commandPrefix: "set -euo pipefail",  // 所有命令前加
});

// 2. 使用自定义 BashOperations（例如执行到远程）
const remoteBashOps: BashOperations = {
  exec: async (command, cwd, { onData, signal }) => {
    // 通过 SSH 执行命令
    const ssh = spawn("ssh", ["remote-host", `cd ${cwd} && ${command}`]);
    ssh.stdout.on("data", (data) => onData(data));
    ssh.stderr.on("data", (data) => onData(data));
    signal?.addEventListener("abort", () => ssh.kill());
    return new Promise((resolve) => {
      ssh.on("close", (code) => resolve({ exitCode: code }));
    });
  },
};

const remoteBashTool = createBashTool("/remote/project", {
  operations: remoteBashOps,
});

// 3. 在 AgentHarness 中使用
const harness = new AgentHarness({
  // ...
  tools: [bashTool],
});

// 4. LLM 调用 bash 时的参数格式
// { command: "ls -la", timeout: 30 }
// timeout 可选，单位为秒

// 5. 中断正在运行的命令
harness.on("tool_call", ({ toolName, input }) => {
  if (toolName === "bash" && input.command === "sleep 999") {
    return { block: true, reason: "Suspiciously long sleep" };
  }
});
```
