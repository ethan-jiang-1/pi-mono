## 四个必须先建立的判断

### 1. chord v2 转正是"替换"，不是"改名"——0011 的双运行时描述整体失效

v1.5.1 内部两步走（chord changelog 两条独立 Breaking）：

- **第一步**：根 export 换 v2；v1 原样移到 `/old` 与 `/old/node`；v1 从根 re-export 的基础件获得独立子路径 `/json`（`JsonValue`/`copyJson`…）与 `/watch`（`Watch`/`NativeWatch` + watch 类型）。仓库内 `src/next`→`src`、`src/next-node`→`src/node`、`src/next-web|react|tui`→`src/web|react|tui`；v1 进 `src/old`，测试与文档同样搬家（`test/next`→`test`、`docs/next`→`docs`，v1 的进 `test/old`、`docs/old`）。
- **第二步**：`/old` 整体删除（含测试与文档）。**同 release 内先搬家再拆房**——changelog 里两条 Breaking 描述的就是这两个 commit。

对 `_digested` 的直接后果：0011 写的"chord 是双运行时并存，写 chord 必须指明哪一套"已经过时；`architecture-next/chord.md`（现役 v1）与 `chord-v2.md`（v2）的分界方式不再成立——**现在只有一个 chord，就是 v2**。v1 语义（cell/cluster/connection 那套 API）只能作为历史记录存在于 sync record。

v2 在本 release 落地的能力面（slices 9–13，每条都是新 export 或新决策）：

- **telemetry across hosts**（slice 9）：`CHORD_TELEMETRY_SCHEMA`、host adapter、`chord.call`/`chord.method`/`chord.commit` 等 span 面、SQLite telemetry store v2（微秒时间戳）、page/worker span 批量上送 server 的 `ingest`（页面批次严格校验：≤100 spans、字段有界、每页每分钟 1,200 上限、盖 `chord.host: browser`）。
- **web/terminal surfaces**（slice 11）：`webSurface`/`tuiSurface` 按 app entry 构建内容哈希 base bundle、插件 facet 以自注册脚本发布、`startPage` 连接循环 + 插件就地换装、React bindings（`HostProvider`/`useHold`/`useWatch`，React 为 optional peer dep）、`startTerminal` 在**沙箱子进程**里跑 app 的终端代码（Node permission model，无 fs/terminal/process/network/SQLite）。
- **plugin model**（slice 12）：按 app 版本化 API 检查每个 import（未列版本/跨 kind/两版本同 facet/直 import chord 都是 build error）、`<name>.<kind>.<ext>` 文件命名、git/npm `installPlugin`、`testPlugin()`。
- **app kit**（slice 13）：`startServer`（数据目录布局、owner link/owner token/设备配对三种登录、0700/0600 权限、拒绝 home/根/他人目录）、`Sessions`（SHA-256 哈希存 token、常量时间比较、400 天未用过期）、`Files`、`exportData`/`importData`（tar 搬迁不停车）、可选 facet `defineUsers`/`inviteFacet`/`ephemeralLoginFacet`。
- **sync layer**（experimental）：`/sync` 子路径——outbox 上传/拉取/折叠/`diverged`/`behind` 语义。
- **live queries**：表 owner 工厂里 `self.query(table, q, limit)`，commit 步内重跑、只发 diff；失败是 `query_failed` HostError 并自愈。
- **i18n**：`defineMessages` 类型化 `t()`、`Translations` registry、`LocaleChoice` 每主体一语言、React/TUI 客户端跟随重渲染。
- **行为决策**：HTTP 默认拒绝（无 principal 且非 `public: true` → 401）、group commit（排队 commit 合一个后端事务）、"call 的 answer 先随 state 发"（乐观值不再闪回旧值）、`host.load` 未调时 `get/hold/registry` 立即 `not_ready`。

### 2. p2/p3 的关系在 README 里写死了：p2 是将被替换的原型，p3 是方向

- `apps/p2/README.md` 顶部 WARNING：**EXPERIMENTAL / "It will be gone soon" / 数据格式与 API 无通知就变**。自托管 Pi Durable UI，独立 chord 插件构成；owner 全权、无服务端文件系统隔离；访客的 TUI facet 在访客机器上的锁定 worker 里跑。
- `apps/p3/docs/README.md`：**p3 = Pi Roam，"one Pi per person"**——人机器上的 server、每 session 一个 worker 进程、其余全是插件，构建于 chord v2 + durable。指南顺序：`process.md` → `chord-practices.md` → `testing.md` → `performance.md` → `names.md`；包规划在 Linear（一包一 issue）。它明确说 `apps/p2` 是"灵感来源，绝不是拷贝来源"。

对 `_digested` 的含义：研究"pi 的产品形态"时，终点不是 coding-agent 的 TUI，而是 p3 的 server+worker+plugin 结构；但 p3 处于早期（v1.5.1 时仅 32 文件），p2 的实现细节不值得深挖。

### 3. coding-agent 工具的"读文件"路径整体换形——扩展作者有两处会破

- **grep**（Breaking）：context 行**来自 ripgrep**，`GrepOperations.readFile` 对 context 行不再被调用（字段保留、标 deprecated，编译不断）。修的是把整个匹配文件读进内存（大文件 OOM）；顺带修 UTF-16 文件与孤 CR。要搜远程系统，override `execute()`（docs 的新 Remote Execution 一节）。同 release：`glob` 相对 `path` 解析（#11895/#10998，0011 post-tag 预告项）。
- **read**：流式读取，只保留要显示的行（#9654）；自定义 `ReadOperations` 可提供新的可选 `createReadStream` 参与流式。
- **edit**：不再改写未触碰行的行尾（CRLF/LF/孤 CR 混合文件），diff 先算、只覆盖变更行及周边（#11751 + OOM 修复）。
- **find/ls**：`limit: 0` 语义修复（<1 视为 1）、恰好 `limit` 条不再误报截断提示、Windows fd 10.5.1 路径模式统一。

### 4. MCP 能力从 coding-agent 下沉到 `packages/mcp`——"嵌入方复用面"变宽

迁入三件套（各自曾是 coding-agent 内部实现）：

- `PipeTransport`：stdio 传输的程序由调用方启动（经 `McpPipe`），配 env daemon 的 `process` 操作，即可在远程/沙箱宿主上跑 MCP server。
- `@earendil-works/pi-mcp/oauth`：两段式登录（`startMcpSignIn()` / `completeMcpSignIn()`），从 coding-agent 迁出。
- 工具命名与配置 helper：`createMcpToolName()`（`mcp__<server>__<tool>`，长名/冲突加哈希后缀）等。

同时一批 MCP 健壮性修复：大 stdio 消息不再反复拷贝扫描（#11761）、CR-only SSE、超限 SSE 连接关闭、stdio 子进程不再在断连后残留（POSIX）、OAuth 回调端口连接及时关闭（#11311）、token 刷新不再覆盖进行中登录的 PKCE verifier。对 `_digested/integration` 的 MCP 章节：**"MCP 客户端是 coding-agent 的一部分"的表述需要弱化**——核心能力在独立包里，coding-agent 是消费方。

### 5. AGENTS.md 三处变化，两处直接影响 Chord v2 Code Style 的适用范围

- 新 Code Quality 规则：**"类型已保证的值不做运行时检查"**（typed 参数/回调结果上禁 `typeof`/`instanceof`/`Array.isArray`/形状守卫；只在决定好的信任边界校验）。这条是 v1.6.1 tagged-union 扫荡的前奏。
- **Chord v2 Code Style 的绑定范围从 `packages/chord/src/next/` 改为 `packages/chord/src/`**；文档/示例路径同步改 `docs/`、`test/examples/`。规则文本本身未变，适用对象变了。
- 新两节：**Writing p2 plugin code**（先读 `apps/p2/docs/plugin-practices.md` 全文）与 **Building p2's web UI**（加载 `.pi/skills/p2-ui.md`）。
- Commands 一节：`apps/p2` 在根 check 与根测试之外（p2 自己 `npm run check`/`npm test`，TUI 测试要 Node 26、浏览器测试要 `CHROMIUM_BIN`）；Chord 与 Durable 的完整测试套件现在**需要 `npm run build`**（Chord 起进程/esbuild 的测试从 `dist/` 加载 workspace 包；Durable import pi-ai 的 `utils/*` 无 source export）。

### 6. ai：Anthropic message threads 与 cache warming 是两个有默认值变化的行为面

- **message threads**（`message-threads-2026-08-12` beta）：带 `sessionId` 的 Anthropic 请求只发新消息，服务端续接；对话变化（compaction、工具列表变化）时回退全量。新增 `StreamOptions.disableContinuation` 退出。**v1.6.0 将默认面扩大**（0014 记录）。
- **cache warming**：`cacheWarming` 策略助手（`getPromptCacheTtlMs()` 等）下沉 ai 包共享，所有 host 用同一套温法；idle 温缓存在 v1.5.1 默认开启（`"idle"`，闲置时最长保温 30 分钟，仅在预期划算时刷新）。
- Breaking：`openai-completions` 对"无工具但历史有工具调用"的请求不再发 `"tools": []`（修 vLLM 0.20+ 400；需旧行为的代理用 `compat.requiresToolsWithToolHistory: true`）。
- 模型面：Claude Fable 5.2（含 server-side Opus 5 fallback 计费说明）、Anthropic 默认模型 → Opus 5.5、多 provider 默认模型整体换新、Azure 1.05M 窗口修正、OpenRouter 输出上限留 15% 余量（修 ~20% 窗口就 compaction 的误判）。
- 新子路径：`@earendil-works/pi-ai/lazy-oauth`、`pi-ai/lazy-bedrock-provider`（bundle 场景的懒加载入口修正）。

## 其它要点（coding-agent 面）

- `pi auth login/logout <provider>`：shell 直登（`--api-key`、`--no-browser` 设备码）；登录 Radius 会顺带配置 Radius MCP server。`/login` `/logout` 列表把伙伴 Radius/OpenRouter 排前（✦ 标记、品牌色高亮）。
- Mermaid 渲染升级：饼图、作者自定义样式、可点击标签（支持超链接的终端）；`pi.registerMarkdownTransformer()` 增 `{ messageTypes }`，transformer 可opt-in `custom`/`summary`/`changelog` 面；内置渲染器也吃 branch/compaction summary。
- `ctx.ui.custom()` overlay 支持 `blocked`（OSC 7501 程序状态上报，从 overlay 显示到 `done()`，含 `setHidden()` 期间）。
- RPC/退出语义：`ctx.shutdown()` 空闲时立即生效（#11599）；shutdown 已开始后 stdin EOF/单信号不再打断（二次信号才立即退）；退出时等待进行中的 token 刷新落盘（修 `invalid_grant`，#11692）。
- `/reload`/会话切换清理**所有**扩展 overlay（含 hidden）；`pi config` 读取 `keybindings.json` 修复；Ctrl+P 单模型作用域修复；会话树/模型选择器后台刷新不再跳选区。
- `pi mcp list` 对 `"auth": { "provider": ... }` 型 server 发 provider token（Radius 型）；`pi mcp login/logout` 的提示改指 `/login`。
- Windows：Ctrl+V/Alt+V 粘贴、PowerShell 5.1 stderr 误报退出码、安装器 `NativeCommandError`。
- 性能/安全零散：image resize worker 串行化（macOS arm64 `zsh: abort`，+15ms/张）、`tool_search`/codemode 读局部 `$ref` 的 `$defs`（#11803 三连）、prompt template 参数保撇号（#11861）、`!`/`!!` 输出折叠状态跟随 ctrl+o。
