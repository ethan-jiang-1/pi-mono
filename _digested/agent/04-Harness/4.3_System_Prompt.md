## 现象是什么

pi-mono 启动后，LLM 看到的 system prompt 不是一段写死的文本，而是多层拼合的结果。不同 mode（interactive、print、RPC）可能通过 `customPrompt`/`appendSystemPrompt` 产生不同的 system prompt。 （硬事实）

最终送到 LLM 的 system prompt 包含：
- 基础 agent prompt（你是谁、有什么工具、怎么用）
- skills 列表（`<available_skills>` XML block，v1.0.0 起需要 read 或 bash 工具可用）
- 项目上下文（`AGENTS.md`、`CLAUDE.md` 等）
- 工作目录（**v0.84.2 已无日期注入**）
- extensions 可能通过 `before_agent_start` 事件修改

## 核心矛盾是什么

System prompt 的构建有几个互相拉扯的力量：

1. **基础 prompt 是静态的**，但 tools/guidelines 会变（哪些工具可用？哪些 guidelines 适用？） （解释）
2. **Skills 来自文件系统**，是运行时发现的，不能硬编码 （解释）
3. **Skills 只在 read（或 bash，v1.0.0 起放宽）工具可用时才有意义**——`<available_skills>` 的消费方式是"用 read/bash 读 SKILL.md"，两者都没有时列出目录是误导 （解释）
4. **Extensions 可能在最后一刻修改** system prompt （解释）
5. **Custom prompt 和 default prompt 走完全不同的构建路径** （硬事实）

## 实现思想是什么

### 两层 system prompt 构建（v1.0.0：只剩一层）

pi-mono 原有两个 system prompt 构建点。**v1.0.0 起 harness 层已删除**，只剩 AgentSession 层：

**~~Layer 1 - AgentHarness 层（`packages/agent/src/harness/`）~~**

~~`AgentHarnessOptions.systemPrompt` 是 `string | (() => string | Promise<string>)`（`agent-harness.ts:251`）~~——**v1.0.0 已随 pi-agent-core harness 删除**（7fd478a2e），存档。

**Layer 2 - AgentSession 层（`packages/coding-agent/src/core/`，唯一现役层）**

`AgentSession._rebuildSystemPrompt()`（`agent-session.ts:1652`，v1.0.0 重锚；v0.84.x 时为 :1066）收集当前状态后经 `buildSystemPromptState()`/`buildSystemPrompt()`（`core/system-prompt.ts:186/:195`）完成拼装。**v1.0.0 起产物是命名 sections 而非单一字符串**：`buildSystemPromptSections()`（:121）产出 `{ preamble, tools, rules, docs, project_context, skills, cwd, ...custom }`——除 preamble 外每段包 `<tag>`、随 `SystemMessage.sections` 进 transcript；`diffSystemPromptSections()`（:204）逐段 diff 后以 patch 追加变更。各段内容（v1.0.0 锚点）：

1. **基础 agent 身份**（`preamble`，:146-147）：固定文本 "You are an expert coding assistant operating inside pi..."；custom prompt 时整段被替换（:143-144）
2. **工具列表**（`tools` 段，:148-151）：`selectedTools`（默认 `["read", "bash", "edit", "write"]`，:58）中**只有提供了 snippet 的工具**才出现，一个都没有时显示 `(none)`
3. **Guidelines**（`rules` 段，`buildRules()` :81-118）：去重合并——工具自带 guideline、条件分支（:101-109：bash+powershell 并存时 "Use bash or PowerShell..."、仅 powershell 时 "Use PowerShell..."、否则 "Use bash for file operations like ls, rg, find"）、固定 "Be concise" / "Show file paths clearly"（:115-116）
4. **Pi 文档指引**（`docs` 段，:153-160）：**无条件**附上 README/docs/examples 路径和"用户问到 pi 自身时才读"的指引；**v1.0.0 "When asked about" 列表加入 docs/mcp.md、docs/codemode.md**（:158）
5. **Skills 块**（`skills` 段，:165-168）：有 skills **且 read 或 bash 任一可用**时 `formatSkillsForPrompt(skills, skillFileReadTool)` 生成 `<available_skills>` block——v1.0.0 闸门从"仅 read"放宽
6. **项目上下文**（`project_context` 段，`renderProjectContext()` :72-79）：`AGENTS.md` 等上下文文件，每文件包 `<project_instructions path=...>`
7. **CWD**（`cwd` 段，:170；无日期行，v0.84.2 起）

### Skills 格式化函数（v1.0.0：只剩一份）

- ~~harness 线：`formatSkillsForSystemPrompt()`（`agent/src/harness/system-prompt.ts:3`）~~——**v1.0.0 已删除**
- 现役（`buildSystemPrompt` 实际用的）：`formatSkillsForPrompt()`（`coding-agent/src/core/skills.ts:355`，新增 `fileReadTool: "read" | "bash"` 参数——闸门放宽，见上文）

它过滤 `disableModelInvocation === true` 的 skills、生成 name/description/location 三字段的 `<available_skills>` XML、所有字段经 `escapeXml()` 转义（`&<>"'`）、按 `fileReadTool` 选择 "Use the read tool ..." / "Use bash to load a skill's file ..." 的头部措辞并提示相对路径按 skill 目录解析。（硬事实，v1.0.0 更新）

### Custom prompt 路径的特殊性

当 `customPrompt` 被提供时（v1.0.0：`system-prompt.ts:143-144`，`preamble` 段被整体替换），构建路径不同：

- 不生成默认的 agent 身份文本、工具列表、guidelines 和 docs 指引（这些都在非 custom 分支 :145-161）
- `appendSystemPrompt` 仍然追加（`addendum` 段，:163）
- 仍然追加 context files 和 skills（若有 read 或 bash，:164-168）
- CWD 作为独立 `cwd` 段追加（:170），custom prompt 与后续拼接内容不再粘连（v0.84 修复的段化延续）

这意味着：**custom prompt 让调用方完全控制 agent 的身份和行为定义**，但上下文和技能注入不受影响。 （解释）

### Model routing 对 system prompt 的影响

v0.84.2 的 `buildSystemPrompt()` 是 **model 无关**的：没有任何 per-model 分支（旧版文档描述的 "OpenAI Codex 需要 static system prompt" 的特殊处理在当前代码中不存在，codex 只出现在 context window 注释和 model alias 里）。模型差异由更底层的 adapter/stream 层消化，system prompt 构建不感知模型。 （硬事实）

### Extension 对 system prompt 的修改

在 AgentSession 中，prompt 提交前会通过 ExtensionRunner 触发 `before_agent_start`（`agent-session.ts:2014-2023`，经 `runner.ts:1411` `emitBeforeAgentStart()`）。**v1.0.0 起 handler 看到的是结构化的 `event.systemPromptOptions`**（normalized 构建选项，含 `sections`/`selectedTools`/`toolSnippets` 等）而不是成品字符串：

```typescript
const result = await this._extensionRunner.emitBeforeAgentStart(
  expandedText, currentImages, this._baseSystemPromptOptions,
);
// handler 可直接编辑 event.systemPromptOptions（如 MCP 扩展写 sections.mcp_servers），
// 或返回 { systemPrompt } —— 后者落为 forceSystemPrompt（runner.ts:1444-1447）：
if (result.systemPrompt !== undefined) {
  currentOptions.forceSystemPrompt = result.systemPrompt;  // 整段 opaque 替换，无 sections
}
// 未被 handler 编辑的 selectedTools 会回落到当前 live loadout（:2021-2023）
```

Handler 还能通过 `event.systemPrompt`（getter）读到"前面 handler 改过的"当前渲染值（`runner.ts:1433-1435`）。修改只对当轮生效——下一轮没有 handler 修改时自动回到 `_baseSystemPromptOptions`。此外每次 prompt 开始时内置扩展会在同一事件里重建自己的段：**MCP 的 `mcp_servers` 段**（`extensions/mcp/index.ts:1016-1019`，`renderServersSection` :188——列出走 codemode/tool_search/deferred 的 server；段变更经 `diffSystemPromptSections` 以 patch 追加进对话，首个 prompt 只等有 direct 工具的 server，其余后台连接后再追加）。 （硬事实，v1.0.0 更新）

### 指令声明的层次

System prompt 的指令存在优先级层次： （解释）

1. **AgentSession 构建的基础 prompt**（最高层，定义 agent 核心身份）
2. **Tools 带来的 guidelines/snippets**（中层，随工具动态变化，`refreshTools()` 后重建）
3. **Skills 注入的领域知识**（通过 `<available_skills>` 和 skill invocation）
4. **项目上下文文件**（`AGENTS.md` 等，代表项目级别的持久化偏好）
5. **Extension 修改**（应用层，可以在最后一刻加入指令，仅当轮生效）
6. **Custom prompt**（覆盖层，完全替换基础 identity） （解释）

## 在 Agent 能力面里的影响是什么

1. **System prompt 是能力注入的主要入口**。工具的 snippet/guidelines 与 skill 列表都由"当前激活了什么"决定。 （解释）

2. **"谁最后改谁做主"的冲突模型**。Extensions 在 `before_agent_start` 中修改 system prompt 的权力最高，但 custom prompt 在 AgentSession 层可以完全替换基础 prompt；extension 的修改按轮失效，避免漂移。 （解释）

3. **Skills 通过 system prompt 被发现，通过 user message 被消费**。Skills 在 system prompt 中作为目录存在，在 user message 中作为内容注入（`/skill:name`，见 4.2）。 （硬事实）

4. **read（或 bash）工具是 skills 注入的闸门**。read 与 bash 都不可用时 `<available_skills>` 整块不生成，避免给 LLM 一个无法兑现的承诺（v1.0.0 起闸门从仅 read 放宽为二选一）。 （硬事实）

## 最小例子是什么

```typescript
// buildSystemPrompt 是 coding-agent 内部函数（不在包的公开 exports 里），
// 仓库内从模块路径引用；SDK 用户通过 settings 的 system prompt / tools 配置间接影响它
import { buildSystemPrompt } from "./core/system-prompt.ts";

// 1. 基础 system prompt（无 custom prompt）
const prompt = buildSystemPrompt({
  cwd: "/home/user/project",
  selectedTools: ["read", "bash", "edit", "write"],
  toolSnippets: {
    read: "Read file contents",
    bash: "Execute bash commands",
    edit: "Edit files with exact text replacement",
    write: "Write or overwrite files",
  },
  skills: [
    { name: "deploy", description: "Deploy the application", content: "...", filePath: "..." },
  ],
  contextFiles: [
    { path: "AGENTS.md", content: "Always use TypeScript strict mode." },
  ],
});

// 输出包含：
// - agent 身份
// - Available tools 段落（只列提供了 snippet 的工具）
// - Guidelines（工具 guidelines + "Use bash for file operations..." + Be concise/Show file paths）
// - Pi 文档路径指引（无条件）
// - <available_skills> XML block（有 skills 且 selectedTools 含 read）
// - <project_context> 块
// - "Current working directory: /home/user/project"（结尾，无日期行）

// 2. Custom prompt（完全替换基础身份）
const customPrompt = buildSystemPrompt({
  customPrompt: "You are a Python expert. Always use type hints.",
  cwd: "/home/user/project",
  skills: mySkills,
  contextFiles: myContextFiles,
});
// 不包含默认 agent 身份、工具列表、guidelines、Pi 文档指引
// 仍然包含 context files、skills（若有 read）、CWD
```

可观察信号：在第 1 个例子里把 `selectedTools` 改成 `["edit", "write"]`（read 与 bash 都去掉），重新构建——`<available_skills>` 块会整体消失，但 "Available tools" 与文档指引仍在；这正是 skills 闸门在起作用（v1.0.0 起 bash 在场时闸门仍开，且措辞切到 "Use bash to load..."）。
