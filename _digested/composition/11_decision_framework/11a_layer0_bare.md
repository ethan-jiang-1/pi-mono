# 11a. 层 0：裸运行

## 什么时候够

裸 pi 什么都不配。它有自己的有效区间——**但很多人高估了这个区间的大小。**

**裸 pi 够用的三种场景**：

1. **一次性问答**："这个函数的复杂度是多少？"——不用读仓库、不用改文件、不用跑命令。直接问答就够了。
2. **文件阅读**："给我解释一下这个模块的架构"——只读就够了，不需要写入。
3. **你已经在这个会话里口头对齐了"要它怎么做"**——对话中说过"不要自动 commit"，agent 记住了。但会话结束就忘。

**裸 pi 不够用的信号**：

| 信号 | 本质问题 | 下一层 |
|------|---------|--------|
| Agent 反复犯同一个错误 | 没有写入"不写会错"的事实 | 层 1 |
| 每开新会话都要重新说规则 | 规则是短记忆，不在 AGENTS.md 里 | 层 1 |
| Agent 改代码后不跑验证 | 没有验证回路的指令 | 层 1 |
| 你有一个每周重复的工作流 | 每次都要重新描述流程 | 层 2 |

## 裸 pi 的 token 基准

裸 pi 的 system prompt 约 5.3k token（`_faq_on_digested/07/06_field_usage.md` C3）。这是你的**预算基准**——每加一层配置，就从这个基准向上加。

5.3k 是什么概念？一个 Claude Code 会话在你说第一句话之前就已经用了 ~20k token 的产品逻辑。所以裸 pi 的 5.3k 不是"最少的"——它是你**配置决策的起点**、你**加东西时的预算剩余**。

## 裸 pi 应该在什么时候升级

**规则**：如果你在同一个会话里对同一件事纠正 agent 第二遍，停下来。别纠正第三遍——先把 AGENTS.md 写好。否则你是在帮 agent 记忆它应该自己记住的东西。
