## 现象是什么

pi-mono 启动后，LLM 看到的 system prompt 不是一段写死的文本，而是多层拼合的结果。不同 mode（interactive、print、RPC）可能通过 `customPrompt`/`appendSystemPrompt` 产生不同的 system prompt。 （硬事实）

最终送到 LLM 的 system prompt 包含：
- 基础 agent prompt（你是谁、有什么工具、怎么用）
- skills 列表（`<available_skills>` XML block，v1.0.0 起需要 read 或 bash 工具可用；v1.0.3+ reader 被隐藏时保留但改为不点名工具的 `"indirect"` 提示）
- 项目上下文（`AGENTS.md`、`CLAUDE.md` 等）
- 工作目录（**v0.84.2 已无日期注入**）
- extensions 可能通过 `before_agent_start` 事件修改

## 核心矛盾是什么

System prompt 的构建有几个互相拉扯的力量：

1. **基础 prompt 是静态的**，但 tools/guidelines 会变（哪些工具可用？哪些 guidelines 适用？） （解释）
2. **Skills 来自文件系统**，是运行时发现的，不能硬编码 （解释）
3. **Skills 只在 read（或 bash，v1.0.0 起放宽）工具可用时才有意义**——`<available_skills>` 的消费方式是"用 read/bash 读 SKILL.md"，两者都没有时列出目录是误导；v1.0.3+ reader 被隐藏时是中间态——仍可经其他工具到达，所以 skills 段保留、只是不点名工具（`"indirect"`） （解释）
4. **Extensions 可能在最后一刻修改** system prompt （解释）
5. **Custom prompt 和 default prompt 走完全不同的构建路径** （硬事实）

## 实现思想是什么

### 两层 system prompt 构建（v1.0.0：只剩一层）

pi-mono 原有两个 system prompt 构建点。**v1.0.0 起 harness 层已删除**，只剩 AgentSession 层：

**~~Layer 1 - AgentHarness 层（`packages/agent/src/harness/`）~~**

~~`AgentHarnessOptions.systemPrompt` 是 `string | (() => string | Promise<string>)`（`agent-harness.ts:251`）~~——**v1.0.0 已随 pi-agent-core harness 删除**（7fd478a2e），存档。

**Layer 2 - AgentSession 层（`packages/coding-agent/src/core/`，唯一现役层）**

`AgentSession._rebuildSystemPrompt()`（**v1.2.0：`agent-session.ts:1704`**；v1.0.3 时为 `:1686`，v0.84.x 时为 `:1066`）收集当前状态后经 `buildSystemPromptState()`/`buildSystemPrompt()`（`core/system-prompt.ts:199/:208`）完成拼装。**v1.0.0 起产物是命名 sections 而非单一字符串**：`buildSystemPromptSections()`（:128）产出 `{ preamble, tools, rules, docs, project_context, skills, cwd, ...custom }`——除 preamble 外每段包 `<tag>`、随 `SystemMessage.sections` 进 transcript；`diffSystemPromptSections()`（:217）逐段 diff 后以 patch 追加变更。**v1.0.3+（#10343）起各段以 declaredTools 为基**：`BuildSystemPromptOptions.hiddenTools`（:20）标记"保持 active 可调、但请求里不声明"的工具（如 codemode `mode: "only"` 隐藏 read/bash），`declaredTools = selectedTools.filter(name => !hiddenTools.includes(name))`（:150），工具列表与 rules 只覆盖声明面。各段内容（v1.0.3+ 锚点）：

1. **基础 agent 身份**（`preamble`，:155-156）：固定文本 "You are an expert coding assistant operating inside pi..."；custom prompt 时整段被替换（:153）
2. **工具列表**（`tools` 段，:157-160）：`declaredTools`（默认 `["read", "bash", "edit", "write"]`，:64）中**只有提供了 snippet 的工具**才出现，一个都没有时显示 `(none)`
3. **Guidelines**（`rules` 段，`buildRules()` :88-125）：基于 `declaredTools` 去重合并——工具自带 guideline、条件分支（:108-116：bash+powershell 并存时 "Use bash or PowerShell..."、仅 powershell 时 "Use PowerShell..."、否则 "Use bash for file operations like ls, rg, find"）、固定 "Be concise" / "Show file paths clearly"（:122-123）
4. **Pi 文档指引**（`docs` 段，:162-169）：**无条件**附上 README/docs/examples 路径和"用户问到 pi 自身时才读"的指引；"When asked about" 列表含 docs/mcp.md、docs/codemode.md（:167）
5. **Skills 块**（`skills` 段，:174-181）：有 skills 且有可用 reader 时 `formatSkillsForPrompt(skills, skillFileReadTool)` 生成 `<available_skills>` block——reader 三态（:174-178）：read/bash **已声明** → 点名工具；reader active 但**被隐藏** → `"indirect"`，提示不点名工具；都不在 → 无 skills 段
6. **项目上下文**（`project_context` 段，`renderProjectContext()` :79）：`AGENTS.md` 等上下文文件，每文件包 `<project_instructions path=...>`
7. **CWD**（`cwd` 段，:183；无日期行，v0.84.2 起）

### Skills 格式化函数（v1.0.0：只剩一份）

- ~~harness 线：`formatSkillsForSystemPrompt()`（`agent/src/harness/system-prompt.ts:3`）~~——**v1.0.0 已删除**
- 现役（`buildSystemPrompt` 实际用的）：`formatSkillsForPrompt()`（`coding-agent/src/core/skills.ts:358`，参数 `fileReadTool: "read" | "bash" | "indirect"`——v1.0.0 闸门放宽为 read/bash 二选一，v1.0.3+ 补 `"indirect"` 第三态：reader 被隐藏时 skills 段保留但提示语不点名任何工具）

它过滤 `disableModelInvocation === true` 的 skills、生成 name/description/location 三字段的 `<available_skills>` XML、所有字段经 `escapeXml()` 转义（`&<>"'`）、按 `fileReadTool` 选择 "Use the read tool ..." / "Use bash to load a skill's file ..."（`"indirect"` 时退化为 "Load a skill's file when the task matches its description."）的头部措辞并提示相对路径按 skill 目录解析。（硬事实，v1.0.3+ 更新）

### Custom prompt 路径的特殊性

当 `customPrompt` 被提供时（v1.0.3+：`system-prompt.ts:153`，`preamble` 段被整体替换），构建路径不同：

- 不生成默认的 agent 身份文本、工具列表、guidelines 和 docs 指引（这些都在非 custom 分支 :154-171）
- `appendSystemPrompt` 仍然追加（`addendum` 段，:172）
- 仍然追加 context files 和 skills（若有可用 reader，:173-181）
- CWD 作为独立 `cwd` 段追加（:183），custom prompt 与后续拼接内容不再粘连（v0.84 修复的段化延续）

这意味着：**custom prompt 让调用方完全控制 agent 的身份和行为定义**，但上下文和技能注入不受影响。 （解释）

### Model routing 对 system prompt 的影响

v0.84.2 的 `buildSystemPrompt()` 是 **model 无关**的：没有任何 per-model 分支（旧版文档描述的 "OpenAI Codex 需要 static system prompt" 的特殊处理在当前代码中不存在，codex 只出现在 context window 注释和 model alias 里）。模型差异由更底层的 adapter/stream 层消化，system prompt 构建不感知模型。 （硬事实）

### Extension 对 system prompt 的修改

在 AgentSession 中，prompt 提交前会通过 ExtensionRunner 触发 `before_agent_start`（**v1.2.0：`agent-session.ts:1894`**，经 `runner.ts:1427` `emitBeforeAgentStart()`；v1.0.3 时为 `agent-session.ts:2048-2060`、`runner.ts:1420`）。**v1.0.0 起 handler 看到的是结构化的 `event.systemPromptOptions`**（normalized 构建选项，含 `sections`/`selectedTools`/`toolSnippets` 等）而不是成品字符串：

```typescript
// v1.2.0：单参数 trigger 对象（v1.0.3 时为三参数 expandedText/currentImages/options）
const result = await this._extensionRunner.emitBeforeAgentStart(
  trigger, this._baseSystemPromptOptions,
);
// handler 可直接编辑 event.systemPromptOptions（如 MCP 扩展写 sections.mcp_servers），
// 或返回 { systemPrompt } —— 后者落为 forceSystemPrompt（runner.ts:1460）：
if (result.systemPrompt !== undefined) {
  currentOptions.forceSystemPrompt = result.systemPrompt;  // 整段 opaque 替换，无 sections
}
```

**`before_agent_start` 在 v1.2.0 是 union**（`core/extensions/types.ts:932-957`），payload 形状按 `messageType` 判别——这是本区间对扩展作者最要紧的变更：

- 两个分支共有：`systemPrompt` getter + `systemPromptOptions`。
- `messageType: "user"`（`BeforeAgentStartUserEvent`）：另有 `prompt` 与 `images?`。
- `messageType: "custom"`（`BeforeAgentStartCustomEvent`）：另有 `message`（`CustomMessage`），**没有 `prompt`**。该分支由 `pi.sendMessage(..., { triggerTurn: true })` 触发。

因此**无条件读 `event.prompt` 的 handler 在一半的 run 上是错的**；读 `prompt`/`images` 前必须先判 `event.messageType === "user"`。触发 `emitBeforeAgentStart` 的 `trigger` 是 `BeforeAgentStartTrigger`（`runner.ts:168-171`）。

Handler 还能通过 `event.systemPrompt`（getter）读到"前面 handler 改过的"当前渲染值（**`runner.ts:1449`**，v1.0.3 时为 `:1444-1446`）。修改只对当轮生效——下一轮没有 handler 修改时自动回到 `_baseSystemPromptOptions`。此外每次 prompt 开始时内置扩展会在同一事件里重建自己的段：**MCP 的 `mcp_servers` 段**（**`extensions/mcp/index.ts:156`=`MCP_SERVERS_SECTION`、`:195`=`renderServersSection`**；v1.0.3 时为 `:152`/`:191`——列出走 codemode/tool_search/deferred 的 server；段变更经 `diffSystemPromptSections` 以 patch 追加进对话，首个 prompt 只等有 direct 工具的 server，其余后台连接后再追加）。 （硬事实，v1.0.3+ 更新行号）

### 指令声明的层次

System prompt 的指令存在优先级层次： （解释）

1. **AgentSession 构建的基础 prompt**（最高层，定义 agent 核心身份）
2. **Tools 带来的 guidelines/snippets**（中层，随工具动态变化，`refreshTools()` 后重建）
3. **Skills 注入的领域知识**（通过 `<available_skills>` 和 skill invocation）
4. **项目上下文文件**（`AGENTS.md` 等，代表项目级别的持久化偏好）
5. **Extension 修改**（应用层，可以在最后一刻加入指令，仅当轮生效）
6. **Custom prompt**（覆盖层，完全替换基础 identity） （解释）

## 在 Agent 能力面里的影响是什么

1. **System prompt 是能力注入的主要入口**。工具的 snippet/guidelines 与 skill 列表都由"当前激活了什么"决定。 （解释）

2. **"谁最后改谁做主"的冲突模型**。Extensions 在 `before_agent_start` 中修改 system prompt 的权力最高，但 custom prompt 在 AgentSession 层可以完全替换基础 prompt；extension 的修改按轮失效，避免漂移。 （解释）

3. **Skills 通过 system prompt 被发现，通过 user message 被消费**。Skills 在 system prompt 中作为目录存在，在 user message 中作为内容注入（`/skill:name`，见 4.2）。 （硬事实）

4. **read（或 bash）工具是 skills 注入的闸门**。read 与 bash 都不可用时 `<available_skills>` 整块不生成，避免给 LLM 一个无法兑现的承诺（v1.0.0 起闸门从仅 read 放宽为二选一；v1.0.3+ 补第三态：reader active 但被隐藏时走 `"indirect"`，段保留、提示不点名工具）。 （硬事实）
5. **隐藏工具的 guidelines 不丢，只是换了位置**（v1.0.3+，#10343）。codemode `mode: "only"` 下 read/bash 的使用约束从 system prompt rules 迁入 codemode 的工具声明（`ToolLoadout.getPromptGuidelines` → `toCodemodeDeclaration` 追加到 description）——对模型语义等价、token 位置不同。 （硬事实）

## 最小例子是什么

```typescript
// buildSystemPrompt 是 coding-agent 内部函数（不在包的公开 exports 里），
// 仓库内从模块路径引用；SDK 用户通过 settings 的 system prompt / tools 配置间接影响它
import { buildSystemPrompt } from "./core/system-prompt.ts";

// 1. 基础 system prompt（无 custom prompt）
const prompt = buildSystemPrompt({
  cwd: "/home/user/project",
  selectedTools: ["read", "bash", "edit", "write"],
  toolSnippets: {
    read: "Read file contents",
    bash: "Execute bash commands",
    edit: "Edit files with exact text replacement",
    write: "Write or overwrite files",
  },
  // Skill 无 content 字段（技能正文按 filePath 读取）；全字段见 core/skills.ts:74 与 core/source-info.ts:6
  skills: [
    { name: "deploy", description: "Deploy the application", filePath: "/home/user/project/.pi/skills/deploy/SKILL.md", baseDir: "/home/user/project/.pi/skills/deploy", sourceInfo: { path: "/home/user/project/.pi/skills/deploy/SKILL.md", source: "project", scope: "project", origin: "top-level" }, disableModelInvocation: false },
  ],
  contextFiles: [
    { path: "AGENTS.md", content: "Always use TypeScript strict mode." },
  ],
});

// 输出包含：
// - agent 身份
// - Available tools 段落（只列提供了 snippet 的工具）
// - Guidelines（工具 guidelines + "Use bash for file operations..." + Be concise/Show file paths）
// - Pi 文档路径指引（无条件）
// - <available_skills> XML block（有 skills 且 read/bash 已声明；被隐藏时为 indirect 提示）
// - <project_context> 块
// - "Current working directory: /home/user/project"（结尾，无日期行）

// 2. Custom prompt（完全替换基础身份）
const customPrompt = buildSystemPrompt({
  customPrompt: "You are a Python expert. Always use type hints.",
  cwd: "/home/user/project",
  skills: mySkills,
  contextFiles: myContextFiles,
});
// 不包含默认 agent 身份、工具列表、guidelines、Pi 文档指引
// 仍然包含 context files、skills（若有 read）、CWD
```
