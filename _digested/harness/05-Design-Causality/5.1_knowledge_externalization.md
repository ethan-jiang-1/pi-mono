# 5.1 知识外置：Pi 把“如何正确参与”放在哪里？

> **局部复核锚点**：`cb18c7cbc89d5becbb4ea2e490a6e7ad0e989f04`。系统/文档/经验分层是研究框架，历史出处见 [方法声明](README.md)，不是 Pi 作者逐字提出的理念。

## 现象是什么

参与知识分布在三类载体：

| 载体 | 当前例子 | 能保证到哪里 |
|---|---|---|
| 可执行检查 | lint/typecheck、依赖/模块图/安装锁检查、贡献门、回归测试 | 检查定义的约束；不覆盖全部语义 |
| 可读规则与示例 | CONTRIBUTING、AGENTS、正式 docs、examples、RFC | 解释合同与用法；示例部分接受类型检查 |
| 参与者判断 | 功能是否属于 core、多个扩展如何组合、威胁模型 | 需要人理解、review 与实践，不是纯机器判断 |

来源：[检查入口](../../../package.json#L20-L27)、[AGENTS](../../../AGENTS.md)、[贡献规则](../../../CONTRIBUTING.md)、[扩展合同](../../../packages/coding-agent/docs/extensions.md)。

## 核心矛盾是什么

把规则写成可执行检查能更早发现特定错误，但还需要维护脚本、测试和输入模型；写成文档也有漂移风险。**外置程度和维护成本是取舍关系，不是已测量的线性比例。** 不能由检查数量推断作者预算或维护者人数。

## 设计判断是什么

### 1. 系统层也覆盖部分参与方式，不能只叫“资产完整性”

[类型检查配置](../../../tsconfig.json#L52-L53)包含 coding-agent examples；[扩展文档](../../../packages/coding-agent/docs/extensions.md#events-and-concurrency)规定事件返回值、顺序和并发行为。类型与运行时合同都能限制部分错误参与方式。

但类型正确不代表扩展语义正确；也不能推出散文每条描述都经过机器验证。这里的结论是**覆盖有边界**，而不是“系统层完全不碰参与方式”。

### 2. 可检查的 examples 是重要桥梁，不是唯一保真材料

根配置检查多数 examples，但 [tsconfig](../../../tsconfig.json#L52-L53)明确排除 gondolin；可执行范本的类型同步也不等于所有运行行为都正确。正式 docs 和类型声明仍是解释合同的来源，不能降格成“散文只做索引”。

合理读法：**当前 docs 找合同，近期 examples 找实现方式，源码和测试验证细节**。三者冲突时记录版本差异，不能预设其中一类总是正确。

### 3. 负知识已经外置，只是分散

“为什么不做某功能”的知识并非都留在人脑：[贡献哲学](../../../CONTRIBUTING.md#philosophy)说明核心范围；[隔离方案](../../../packages/coding-agent/docs/containerization.md)说明权限边界；[作者历史自述](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)直接说明当时跳过 TODO、plan mode、sub-agent 等能力的理由。

本次没有核到统一且机器校验的“被否方案总表”。这只说明**检索入口分散**，不能说“负知识未外置”，也不能断言维护者主动接受所有文档漂移。

## 影响是什么

1. **贡献者**：先读规则和当前合同，再结合范本；代码改动按 AGENTS 跑相应检查，贡献前按 CONTRIBUTING 准备。
2. **维护者**：新增文档或检查应说明覆盖目标和维护成本，不用“所有规则都必须机器化”作为默认前提。
3. **嵌入者**：类型检查帮助核对接口；生命周期、状态恢复和业务策略仍需宿主验证。

## 最小例证与核对入口

- examples 引用不存在的 API，可能被类型检查发现；改错一段 Markdown 的语义，类型检查通常不能发现。**这是验证能力不同，不是任何一类材料绝对可靠。**
- [runtime-deps 负例测试](../../../scripts/check-runtime-deps.test.mjs#L27-L34)故意制造未声明依赖，并断言检查拒绝。它说明机器规则本身也可以被回归验证；具体覆盖分析见 [5.3](5.3_paved_road_friction.md)。
- 原生理念证据另见 [FAQ 研究账本](../../../_faq_on_digested/12_pi_philosophy/research.md)，不要以本页分析框架代替作者自述。
