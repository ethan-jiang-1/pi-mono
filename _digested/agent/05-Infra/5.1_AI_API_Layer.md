# 5.1 AI API Layer：wire-protocol streaming 与 lazy loading

> **⚠️ v0.84.x**：① `ModelsStreamTransforms` 改名 `ModelsRequestTransforms`（header 变换作用于所有已认证 provider 请求）；② Mistral 从 SDK transport 换成**原生 Chat Completions HTTP stream**（删掉 generated client 和 schema runtime 开销）——"每个 API 一个 adapter"的叙述更成立了；③ 新增 deferred provider request contracts（durable response handles、authenticated fetch/cancel dispatch、faux-provider）；④ OpenAI Responses deferred tool loading 支持 message-anchored `additional_tools`；⑤ `StreamOptions.samplingParams` 透传任意 OpenAI-compatible 采样参数。

## 现象是什么

v0.83.0 中 `packages/ai/src/` 新增了 `api/` 目录（31 个文件），把原来混在 `providers/` 里的 wire-protocol 实现（怎么调 Anthropic Messages API、怎么调 OpenAI Responses API...）拆出来成为独立层。每个 API 有两个文件：一个实现（如 `anthropic-messages.ts`）+ 一个 lazy wrapper（如 `anthropic-messages.lazy.ts`）。同时 `auth/` 和 `compat/` 也从 providers 中拆出。

## 核心矛盾

**API adapter 的代码很重。** `bedrock-converse-stream.ts` ~38KB 带 AWS SDK 依赖，`openai-responses-shared.ts` 有复杂的 tool output 转换逻辑。如果启动时 eager-load 所有 adapter，即使只用 Anthropic，也要为 AWS SDK、Google SDK、Mistral SDK 付出 import 成本。

解法：**lazy loading 模式** — 从 `.lazy.ts` import 几乎是零成本的（一个闭包），真正的模块在第一次 `stream()` 调用时才加载。

## 实现思想

### 三层架构

```
providers/   →  "有什么模型"（Model catalog，纯数据）
api/         →  "怎么调 API"（Wire-protocol streaming）
auth/        →  "用什么凭证"（Credential resolution）
```

调用链：`ModelRuntime.streamSimple()` → 按 model 的 `api` 字段 dispatch → 找到对应的 `ProviderStreams` → 调 `stream()` 或 `streamSimple()`。

### lazyApi 和 lazyStream

`lazy.ts` 导出两个函数：

**`lazyApi(load): ProviderStreams`** — 接收 `() => import("./xxx.ts")`，返回一个 `{ stream, streamSimple }` 对象。首次调用任一方法时触发 `load()`，结果缓存在模块闭包中。后续调用直接走缓存。

**`lazyStream(model, setup): AssistantMessageEventStream`** — 更深的技巧：**同步返回**一个 `AssistantMessageEventStream`，而 `setup()` 在后台异步运行。如果 setup 失败（模块加载失败、auth 错误），错误编码为 stream 上的 error event，永不 throw。

这意味着调用方总是立即拿到 stream 对象——不需要 `await`。网络请求 + 模块加载并行进行。

### Stream 函数合约

每个 API 模块导出两个函数，遵守相同的合约：

```ts
stream(model, context, options?) → AssistantMessageEventStream
streamSimple(model, context, options?) → AssistantMessageEventStream
```

合约规则：
- **永不 throw**。所有错误（网络、auth、parse）编码为 stream event
- **成功**：`{ type: "done", message: AssistantMessage }` → stream 结束
- **失败**：`{ type: "error", ... }` → `AssistantMessage` 带 `stopReason: "error"` 和 `errorMessage`

`stream` 接收 provider-specific 的 typed options（如 `OpenAIResponsesOptions` 有 `reasoningEffort`）。`streamSimple` 接收统一的 `SimpleStreamOptions`（有 `reasoning`、`thinkingBudgets`），内部通过 `buildBaseOptions()` 自动 clamp maxTokens 到 context window 安全边界，然后调用 `stream`。

### 每个 `.lazy.ts` 的结构

所有 lazy wrapper 都是同一模式的一行代码：

```ts
// anthropic-messages.lazy.ts
export const anthropicMessagesApi = (): ProviderStreams => lazyApi(() => import("./anthropic-messages.ts"));
```

Bedrock 是个例外——它用变量字符串（非字面量）传 import path，防止 bundler 追踪到 Node-only 的 AWS SDK。同时暴露 `setBedrockProviderModule` 供 Bun binary 注入静态 bundle。

### cross-provider 共享模块

`transform-messages.ts` — 跨 provider 消息标准化：image downgrade、tool-call ID 重写、orphaned tool-call padding、加密 thinking signature 剥离。

`constrained-sampling.ts` — grammar-based 约束 JSON 采样 + JSON Schema strict mode 解析。工具可以声明 `constrainedSampling` 配置，API adapter 据此启用 provider 的 structured output 能力。

`openai-responses-shared.ts` — OpenAI Responses 家族的共享转换逻辑（tool output → message、text signature 编码、caching helper）。

## 在 Agent 能力面里的影响

- **启动零成本**。import `@earendil-works/pi-ai` 不再加载 AWS SDK、Google SDK 等重型依赖。
- **添加新 provider** 只需：实现 `ProviderStreams` 合约 + 写一行 lazy wrapper + 在 `compat.ts` 的 `BUILTIN_APIS` 表中注册。
- **错误面统一**。所有 API 错误以 event 形式流入 Agent loop，不需要 per-provider try/catch。
- **`streamSimple` 是外部集成的最简路径**：只传 model + context + reasoning level，maxTokens 自动 clamp。

## 最小例子

直接使用一个 lazy API adapter：

```ts
import { anthropicMessagesApi } from "@earendil-works/pi-ai/api/anthropic-messages.lazy";

const api = anthropicMessagesApi(); // 零成本——还没加载 Anthropic SDK

const stream = api.streamSimple(model, context, {
  reasoning: "high",
  apiKey: "sk-...",
});
// stream 是同步返回的 AssistantMessageEventStream
// Anthropic SDK 在第一次 stream 调用时才 import

for await (const event of stream) {
  if (event.type === "text_delta") console.log(event.delta);
  if (event.type === "done") break;
}
```
