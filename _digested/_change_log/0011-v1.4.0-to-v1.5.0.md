## 五个必须先建立的判断

### 1. `pi-schema` 是"低层依赖"，不是"新增能力"

- `packages/chord/package.json:93-94` 现在依赖 **两个** Pi 包：`@earendil-works/pi-schema: 1.5.0` 与 `@earendil-works/pi-telemetry: 1.5.0`；`typebox` 已从 dependencies 消失。
- `packages/schema/src/formats/typebox/` **直接搬了 TypeBox 的 format 实现**，`packages/schema/LICENSES/typebox-LICENSE` 在包里——这是"接管"，不是"并列"。
- `coerce` 的语义被明确定义为 **TypeBox 1.3.27 `Value.Convert` 规则的超集**（`packages/schema/README.md`）。目标就是替掉 TypeBox 并多给一点。
- API（`packages/schema/src/validator.ts:14-27`）：`compile(schema, options?)` 返回 `Validator`；`compile(schema, { coerce: true })` 返回 `CoercingValidator`。`Validator.check` 是布尔快路径，`errors(value)` 给 JSON Pointer 路径，`CoercingValidator` 另有 `coerce(value)` 与 `parse(value)`（`validator.ts:32,50,58,67,73`）。
- 入口只有两个（`packages/schema/package.json` exports）：`.` 与 `./formats`。

**文档含义**：不是"又多了一个可选工具"，而是"工具参数校验的底座换了"。要写行为差异，不只是改名。

### 2. TypeBox 的退场对扩展作者**部分兼容**，写错就误伤读者

`packages/coding-agent/docs/extensions.md:172-184` 有一节 `### Tool parameter schemas and TypeBox`，明确三层：

| 层 | v1.5.0 状态 |
|---|---|
| 扩展源码写法 | 仍可从 `@earendil-works/pi-ai` import `Type`/`Static`/`TSchema`——coding-agent 映射到 pi-ai 的 compat entry + 内置 TypeBox；内置工具工厂返回 `TypeBoxAgentTool` |
| 参数校验 | 一律 pi-schema（`compile(schema, { coerce: true }).parse()`），JSON Schema 之外特性**不生效** |
| 新代码建议 | pi-schema builders；`obj` **默认 closed**，要开放需 `{ open: true }` |

**静默语义变化**（不是改名，是行为）：
- `format` 的校验面收窄：`{type:"string", format:"email"}` **仍拒绝** `"nope"`（标准 format 有 vendored 表 + 显式 `formats` 清单）；被丢弃的是 `Format.Set()` 注册的自定义 format。相对 TypeBox 是**收紧**，不是放松。
- `Type.Refine()` 不跑；`Type.BigInt()`/`Type.Undefined()`/`Type.Void()` 拒绝一切 JSON 参数；codec 不解码；`Format.Set()` 注册的 format 不检查。
- 属性名是名字不是正则；`$ref` 悬空只拒绝该位置的参数，而非整个调用。
- 校验错误文案换成 pi-schema 的：`- path: missing`、`- limit: expected number, got string`。
- 反向放宽：纯 JSON Schema 工具（含 MCP 工具）现在**也**获得强制转换（数字字符串→数字、单值→数组等）。

### 3. chord 是**双运行时并存**，不是升级

`packages/chord/package.json` exports 里 `./next` 在 v1.5.0 **首次出现**（v1.4.0 无此导出）。同时 v1 自身也在本轮大改：

- **v1 换 pi-schema**：`Format.Set()` 自定义 format 丢弃（标准 format 仍校验）、`invalid` 错误文案换、`details` 变 pi-schema 的 `ValidationError`；同一 JSON 的 fingerprint 不变。

- `traceIn(options, fn, context)` 参数顺序改为 context 最后；`SqliteExecutor.runCounted()` 新增。

**v2 的体量**（`packages/chord/src/`）：
- `next/`：`store` 34、`host` 31、`documents` 13、`contracts` 13、`link` 12、`jobs` 10、`remote` 10、`data` 8、`registries` 7、`state` 7 = 145，**+ 根部 `index.ts` = 146 文件**
- `next-node/`：`http` 13、`plugins` 9、`workers` 6 = 28，**+ 根部 `compression.ts` = 29 文件**
- `docs/next/`：**33 篇 md**，其中 `design.md` **2,554 行**、`decisions.md` **2,957 行**、`slices.md` **230 行**
- `test/next/examples/`：**144 个文件**，但其中只有 **46 个编号示例**（32 个单文件 `.ts` + 14 个目录，编号 01–48 非连续），递归 101 个 `.ts`
- `esbuild` 与 `ws` 是 **optional peer dependency**（`peerDependenciesMeta` 均为 optional）——chord 没有变重。

**v2 五个新能力面**：plugins（esbuild 构建 + `vm.Script` 求值 + mapStack + 热 reload + 跨插件按名导入）、registries（`defineRegistry`/`contribute`/`self.registry`）、HTTP（Web 标准 `fetch` handler + CSP nonce + 签 cookies）、workers（`createWorkers`/`workerMain`）、store（`commitSeries`、document histories `none|latest|rewindable`）。

**文档含义**：v1.4.0 的 `architecture-next/chord.md` 描述的是**现役 v1 运行时**，没失效但不完整。v2 必须独立成页，且 `design.md`（是什么）与 `decisions.md`（为什么不是另一种做法）要并读——只引 design 会写出"这是唯一做法"的错误印象。

### 4. durable 的 34 条 Breaking 有**一条主线**，分四组

不要按 changelog 顺序写。因果四组：

**(A) 提交模型** — `Storage.commit(writes, adopt, ctx)` → `commit(batches, receive, context): Promise<CommitResult>`（`packages/durable/src/types.ts:1340-1344`）。`CommitResult = { stored: number; refused?: unknown }`（`types.ts:1313`）。每个 batch 是一次独立原子提交、各自 seq、检查看到前面 batch 的写入；第一个被 Durable 自身检查拒绝的 batch 不入库，其前的入库，`refused` 带回原因；其他失败（驱动/IO/COMMIT 失败）整体 reject 且视为未知结果。另有可选 `publishing(publish, ctx)`（`types.ts:1353`）、`mintId()` 契约收窄（`types.ts:1359-1363`）、`commitSeries`（chord v2 store，`store/store.ts:323`）。测试播种用 `commitWrites()`。

**(B) 观察模型** — `watchEvents()` 及 `AgentEvent`/`AgentEventStream`/`SnapshotEvent`/`MessageChange`/`ToolEventCall` **整套删除**（全仓仅剩一处注释提到它：`packages/durable/test/harness-view-run.test.ts:2`「This replaced the event stream (`watchEvents`, #11327)」）。替代是**渲染状态而非拼装事件**：`ConversationView` 变成 transcript 的**窗口**（`min` 默认 50、`max` 默认 `2*min`），`Conversation.entries()` 分页，`ConversationTranscript` 客户端合并，`Conversation.context()` 给出模型看到的活跃 transcript。三个 state getter `documentState()`/`viewState()`/`taskGraph()` 删除，改用 `watchDoc()`/`Conversation.watch()`/`Harness.watchTaskGraph()`。`subscribeCommits()` → `observeCommits(observer)`（`types.ts:1262`，观察者形状 `types.ts:1118`）。

**(C) watch 换形** — 跟随 chord v1 的新形状（`WatchHandle`/`WatchCall`/`WatchEnd`），durable 转导出 `WatchChange`/`NativeWatchChange`。`retired` 变 change 字段而非 end；同一地址的新文档在同一条 watch 上到达（`[["r", value]]`）；listener 忙时的帧折叠：append 合并、同字段 set 取最后、超 10,000 个挂起操作退化为一次整根替换。`FileSystem.watch()` 的 change 类型改名 `WatchChange`→`FileChange`。

**(D) 持久化时机** — partial answer 与运行中的工具输出的节流提交 **deferred**（`CommitPersistence`）：watches/views 立即可见，Storage 在"下一次读 `pi.live` 的提交"时一起拿到，最迟 `settings.progress.persistWithinMs`（默认 **1,000 ms**，`packages/durable/src/harness/agent.ts:37`）。收益：32 路流 over SQLite 事务少 ~5.7×、磁盘写少 ~2.9×；长回答 27×/9×；CPU 约 −25%。代价：**崩溃最多丢约 1 秒流式内容**（原 ~100 ms）。`subscribeCommits()` 只在这些提交落盘后收到；要展示实时进度应改用 `watchDoc()`/`Conversation.watch()`。

零散但会打到读者的：restart-limited 任务**不再 park 而直接结束**（`restart_limit` 语义变了，`Harness.retryTask()` 放行路径改变）；`pi.live` 不再在无答案结束时为空，保留 `runFailure`（`RunFailure`/`RunFailureReason`，新增 `nothing_to_answer`/`turn_limit`/`interrupted`）；`pi.live.run` 新增必需 `turns`；`afterTool` 对**每个**工具结果都跑（含错误结果与未提供工具的调用，后者带 `unoffered: true`）；`CompactionStatus.reason`→`trigger`；`TaskInspection.state` 的 `ready`→`pending`；`SessionEnd`/`ReportFrom`/`DocumentCommitChange` 全部 tagged by `kind`；新增 `StoreStorage`（Durable 的 `Storage` 落在 Chord v2 的 store 上）。
