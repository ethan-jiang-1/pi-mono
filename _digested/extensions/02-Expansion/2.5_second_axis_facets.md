# 2.5 第二条扩展轴：进程/环境放置轴（chord 插件）

> 本页曾整页描述 v0.85.x 的 chord facet/service 体系（`chord.facets` host→entry 映射、`pi-example-plugin` 活证据、`api.ts` 行号锚点）。**该体系已消失**：v1.2.0 被 chord2 重写删除，v1.5.1 起 chord v2 转正为唯一运行时、v1 整体删除。按"旧行为只进 sync record"的语料规则，本页压缩为概念 + 现状 + 历史三段；v0.85.x 的逐条取证见 `_change_log/0009`/`0010`/`0012`。

## 这条轴是什么（概念，仍成立）

前面 2.1–2.4 四条轴切的是"**沿 agent 循环的哪个接缝、注入什么**"；这条轴切的是"**同一份 feature 的代码跑在哪个进程/环境**"。它不是四条轴的第五条：一个工具可以既走 `registerTool`（改行为/长相），又以插件形态把自己的 server 侧与客户端侧拆到不同进程。概念详解见 [`composition/10_extension_axes/10i_process_axis.md`](../../composition/10_extension_axes/10i_process_axis.md)。

## 现状（v1.6.1）：chord v2 的插件模型

今天的"第二条轴"由 chord v2 承载：**facet**（插件对一个 host 的声明——serve 哪些类型、对 registries 贡献什么）、按 app 版本化 API 的 import 检查、`<name>.<kind>.<ext>` 文件形态（`contract.web.tsx` 即 web kind）、git/npm `installPlugin`、`testPlugin`、esbuild 构建 + `vm.Script` 求值 + 按 host 逐个 rollout 的热重载、web/terminal surfaces（终端跑在访客机器的沙箱 worker 里）。插件间共享值走 registries；跨进程引用走 host/link。

- 权威描述：[`architecture-next/chord.md`](../../architecture-next/chord.md)（单页 v2）与 `packages/chord/docs/plugin-authoring.md`（插件作者指南）。
- 真实样本：`apps/p3`（"one Pi per person"，插件即一切）；`apps/p2`（插件式 Web UI 原型）。
- AGENTS.md 已为这层立法：Writing p2 plugin code / Working on p3 (Pi Roam) packages 两节。

## 与 `core/extensions` 的关系：并存，服务不同宿主

| 维度 | extension 系统（轴 2.1–2.4） | chord 插件（本轴） |
|---|---|---|
| 归属 | `packages/coding-agent/src/core/extensions/`（Pi 自有） | `packages/chord` v2（应用中立） |
| 作者形状 | 单个工厂 `export default function (pi: ExtensionAPI)` | 一个包多个 facet 文件（按 kind 拆） |
| 运行位置 | 宿主（coding-agent）进程内 | 按 host 拆 bundle，跨 server/workers/浏览器/终端 |
| 生命周期 | 加载期注册 + 运行期回调 | 声明式；factory 只声明，Chord 激活；reload 按 host rollout |

两者**不是替代关系**：coding-agent 的扩展系统服务"给 Pi 本体加能力"；chord 插件服务"用 chord 组装的应用加能力"（p2/p3 里没有 `ExtensionAPI`，只有 facet）。

## 术语碰撞（必须显式声明）

"extension" 一词在 pi-mono 里至少三个义项：① `core/extensions` 的扩展（本目录 2.1–2.4 的用法）；② **分发 chord 插件的包**（v0.85 的 plugins.md 用法，今天对应 chord v2 的 `installPlugin` 包形态）；③ 整个插件层（旧文档 "the extension layer"）。本目录不声明义项时一律指 ①。
